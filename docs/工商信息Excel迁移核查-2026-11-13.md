# 工商信息Excel迁移核查

日期：2026-11-13。状态：首批原式实测已保存；港股当前字段定义仍待补查，桌面工具暂停，尚未批准生产改造。

## 已确认范围

- 用户希望统一iFinD取数渠道，先核查A股（含沪深B股、北交所）与港股工商信息`profile`迁移至iFinD Excel的可行性；有确需用户处理的资料、认证或业务口径选择时再询问。
- 本轮不扩展美股，不修改IPO、股东、分红、预测或财报补充；不因迁移顺带更改字段分组。
- 现行行为见[架构§5](market-data架构设计.md#5-公司信息获取工具-get_company_profile)；工商24项与IPO20项的原分组提案仍见[原方案](market-data-公司工商与证券IPO调整方案-2026-11-05.md)，不把本次核查当成该提案已实施。

## 核查顺序

1. 以[Excel手册索引](../reference/ifind-Excel公式索引说明-20181218.md)、用户已有模板及当前已安装插件资料为公式依据。先核对指标码、参数和当前字段对应；不猜码、不套用SDK参数、不因旧手册未收录而直接要求用户重供。
2. 只读检查Excel运行状态，先单项验证，再对一个样本的工商字段逐项核对；首个样本返回形态确认后才扩至其他市场代表样本。只使用独立测试产物，不写正式业务缓存。
3. 区分公式报错、真实空值、日期序列值、文本值及比例单位；保留完整原始结果和公式来源。发现意外工具故障时停止扩大测试，报告具体障碍。
4. 核查员工人数依赖的最新报告期能否一并走Excel，避免工商主字段迁移后仍隐藏依赖SDK。
5. 检查现有“申万行业”名称与同花顺行业原式的差异，以及运行层取数后清空工作页与用户查看公式目标的关系；不在核查时擅自决定口径或修改运行层。
6. 将上游客观实测写入[支持情况](../字段与数据源支持情况.md)，原始取数证据保存在`excel-probe/runs/20261113-company-profile/`；临时探针只放`.codex-temp/`并在用完后删除。

## 实施前边界

本轮授权为资料核查与验证，不直接切换生产通道、清空缓存、修改用户模板、导出或推送。核查完成后在本稿列出具体迁移改动与验收要求，再按用户确认实施。现行接口与行为文档保持当前事实。

## 拟迁移改动（待确认，不实施）

1. 复用现有[Excel运行层](Excel常驻运行层.md)与文本模式，为`profile`构建市场对应的已验证公式；不新增一套Excel进程或账号登录管理，不调用SDK作为工商字段的失败回退。员工人数依赖的最新报告期也一并走Excel。
2. 在[公司信息调度](../src/market_data_mcp/company_service.py)中仅切换A/B股、北交所及港股的`profile`路由；接口签名、完整返回、30天缓存、范围刷新及MCP/CLI共用逻辑保持。其他信息类型及财报补充维持原通道，因此本阶段不移除项目整体SDK依赖。
3. 工商缓存使用明确的Excel来源标记，按需重取目标公司，不批量清空旧缓存。SDK或东财旧值不得冒充Excel取数成功，也不混入同一字段。港股旧section缓存保留，不借本轮修改其他类型。
4. 现有字段分组原则上不变；行业名称与实际指标的冲突须先确认。港股若存在不能等价提供的字段，必须先决定保留范围与口径，不能悄悄删项、改名、把0统一转为空值或用其他源补齐。
5. 取数后是否保留可见公式供用户查看另行确认；不直接取消行情共用运行层的清理，也不把临时公式保存进用户模板。
6. 确认实施后同步[架构§5](market-data架构设计.md#5-公司信息获取工具-get_company_profile)、帮助及必要入口说明；原式及客观能力只在支持情况维护。
