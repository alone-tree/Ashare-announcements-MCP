# THS_DR表函数使用说明（2026-11-23实测）

记录iFinD Excel插件中 `THS_DR` 这一函数的调用方式和实测结论。它与项目原有的 `thsiFinD` 是两套不同机制，不互相替代：`thsiFinD` 取单值，`THS_DR` 取整张表。

## 一、它和thsiFinD的区别

| 项目 | thsiFinD | THS_DR |
|---|---|---|
| 输入 | 指标码 + 代码 + 日期 + 报表类型等 | 报表编码 + 输入参数名 + 输入参数值 + 输出字段代码 |
| 输出 | 单值，一公式一值 | 二维表，函数写到指定区域 |
| 输出定义 | 由指标码决定 | 由输出区首行的字段代码决定 |
| 前置条件 | 无 | 输入参数值与输出字段代码须先手工填好 |
| 现有支持 | 公式库753条已验证 | 本项目此前无记录，本文件为首份 |

用途上取长补短：`THS_DR` 用于取 `thsiFinD` 没有的指标（成分股名单、分地区收入、客户供应商集中度这类表格型数据），不改变现有 `thsiFinD` 的取数路径。

## 二、公式结构

实测通过的原式（工作表 `data` 页）：

```
=@THS_DR("p03473","iv_date,iv_zsdm",D6:D7,C8:E8)
```

四个参数：

| 位置 | 实测内容 | 含义 |
|---|---|---|
| 1 | `"p03473"` | 报表编码。本项目目前只确认 `p03473` 一个 |
| 2 | `"iv_date,iv_zsdm"` | 输入参数名，逗号分隔，与第3参数的格数一一对应。`iv` = input variable |
| 3 | `D6:D7` | 输入参数值区域，按顺序填入第2参数各名字的值 |
| 4 | `C8:E8` | 输出区域，首行须预填输出字段代码，决定返回哪几列 |

第2、3参数是输入，第4参数是输出，两者不要混淆：

| 参数名（第2参） | 对应格（第3参） | 实测填值 |
|---|---|---|
| `iv_date` | D6 | 20261123（日期） |
| `iv_zsdm` | D7 | 000300.SH（指数代码） |

输出哪些列由第4参数首行的字段代码决定，形如 `p03473_f001`、`p03473_f002`、`p03473_f003`（`f` = field），与第2参无关。

`p03473` 的实测行为：输入日期与指数代码，返回该指数在该日的成分股名单，三列依次为日期、同花顺代码、证券名称。

## 三、两个容易误解的点

### 3.1第2参是输入参数名，不是要返回的字段

`iv_date`、`iv_zsdm` 是输入变量名，分别对应D6、D7两格的值。它们不决定输出哪几列。

判据：把第2参写成只含一个名字 `"iv_date"`，第3参仍给两格值，结果取不到数据。若第2参真是"字段清单"，少写一个只会少一列；实际是失效。

### 3.2输出区首行必须预填字段代码

第4参数区域的首行要先写好输出字段代码 `p03473_f001` / `f002` / `f003`。不填则函数只回显参数、不写入数据。

实测隔离（同一实例、同一公式，只改动是否预填）：

| 预填C8:E8 | 输出区 | 结果 |
|---|---|---|
| 否 | C8:E400 | 失败，只回显参数 |
| 否 | C8:E8 | 失败，只回显参数 |
| 是 | C8:E8 | 成功 |
| 是 | C8:E400 | 成功，一次返回301行 |

起作用的是预填字段代码，不是区域大小。曾误判为"输出区必须恰好等于列数"，已由第4行否证。

### 3.3输入确实会被采用（换值验证）

换输入，输出随之改变，证明第2、3参是真输入而非摆设：

| 改动 | 输出第10行起 |
|---|---|
| D7 = 000300.SH | 平安银行、万科A、中兴通讯 |
| D7 = 000905.SH | 中国宝安、深科技、深圳能源、深桑达A、神州数码 |
| D6 = 20261123 | 第一列显示2026-11-23 |
| D6 = 20250102 | 第一列显示2025-01-02 |

### 3.4 C5与D5的回显不用手填

C5显示"报表名称"、D5显示"指数成份"，是公式自己写出的回显。不填D5也能正常取数（实测两种情况都返回301行）。

## 四、完整操作顺序

按此顺序写，缺一步都取不到数：

1. 清空 `data` 页。
2. 填输入参数值：`D6` = `20261123`，`D7` = `000300.SH`。
3. 填输出字段代码：`C8` = `p03473_f001`，`D8` = `p03473_f002`，`E8` = `p03473_f003`。
4. 在公式格写 `=@THS_DR("p03473","iv_date,iv_zsdm",D6:D7,C8:E400)`，公式格选在参数区之外的空白位置（实测用 `C5`）。

## 五、返回数据的落点

以 `C5` 放公式、`C8:E400` 为输出区为例，实测布局如下：

| 位置 | 内容 |
|---|---|
| C5 | 报表名称（文本，公式回显） |
| D5 | 指数成份（报表中文名，公式回显） |
| D6 / D7 | 输入参数值回显 |
| C8:E8 | 输出字段代码 `p03473_f001` / `f002` / `f003` |
| 第9行 | 中文列名：日期 / 同花顺代码 / 证券名称 |
| 第10行起 | 数据 |

沪深300实测共301行数据，`UsedRange` 到第309行。

## 六、等待数据完成的方式

不能沿用 `fetch_matrix` 的判断逻辑。`fetch_matrix` 靠"单元格是否还在显示抓取/提取"和Excel计算状态判断，而 `THS_DR` 是往区域里逐步追加行，判断依据应是行数不再增长。

实测时序：写入公式后约1秒数据即到位（301行），之后不再变化。判稳策略取"连续多轮有数据行数不变"。

注意：本项目此前的探针脚本曾因只判断固定时长、不判断数据是否到位，导致Excel早已出数却仍空等45秒。接进CLI时必须用行数判稳，不要用固定等待。

## 七、未确认事项

以下均未实测，不写入结论，需要时向用户索取插件界面原文：

- `p03473` 之外还有哪些报表编码，各自对应什么数据。
- 每个报表编码有哪些可用输入参数名（`iv_date`、`iv_zsdm` 之外）和输出字段代码（`p03473_f00X` 之外）。
- 输出字段代码的可选范围与含义，目前只知f001/f002/f003依次是日期、同花顺代码、证券名称。
- 输入参数名与第3参格数不匹配时的报错形式。

按项目铁律，iFinD参数严禁猜测变体，以上只能由插件界面原文确认。
