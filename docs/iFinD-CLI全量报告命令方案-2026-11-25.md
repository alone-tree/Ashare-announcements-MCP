# iFinD CLI 全量报告命令方案

日期：2026-11-25
状态：已实现（2026-11-25），待验收
关联：[固定报告与绘图扩展方案](iFinD-CLI固定报告与绘图扩展方案-2026-11-25.md)、[包说明](../src/ifind_excel_tool/README.md)

实现结果：`report` 命令一条完成取数、单位换算、绘图、拼Markdown、落盘。
用户后续两项决定已落实：预测年份按年报推（2026年报未出则预测2026年，出了则预测2027年）；行情图固定用「总市值与前复权收盘价」双轴模板（左轴总市值、右轴前复权收盘价），有事件CSV则标注，没有则不画。
验收样本：`D:\工作与投资研究\研究项目\01-公司与标的\世嘉科技\CLI全量报告-2026-11-25\`。

## 一、目标

一条命令完成单公司全量数据导出：取数、单位换算、排版、绘图、落Markdown，输出到指定目录。替代当前"逐板块 fetch_scene 再手工 export_report"的多步流程。

不做的事：Markdown 转 Word、衍生财务指标（同比增长率、ROE、毛利率等）、公司级适配。

## 二、报告期口径

### 2.1 依据

旧脚本 `上市公司标准数据提取.py` 的 `select_periods()` 与 iFinD 模板 `0-IPO信息+财报数据 ifind.xlsx` 的整理层是同一套逻辑的两次独立实现，互相印证：

- 最新报告期由 `ths_regular_report_latest_rp_stock` 现探，不手填
- 后续列由年份减1推导
- 铺几列由模板列宽决定

xlsx 证据：

| 表 | 列 | 构成 |
|---|---|---|
| 整理资产 | C:J 8列 | 最新期 + 上一年年报 + 逐年年报 |
| 整理利润 | C:K 9列 | 最新期 + 去年同期 + 年报… |
| 整理现金流 | C:K 9列 | 同整理利润 |
| 盈利预测 | C:I 7列 | FY3/FY2/FY1 + 最新年报 + 前三年 |

三表表头 D3:AK3 是 34 个手填日期常量，不是公式。

### 2.2 本方案采用的口径

统一7列，与老脚本一致：

| 数据 | 列构成 |
|---|---|
| 资产负债表 | 最新期 + 上一年年报 + 更早年度，共7 |
| 利润表、现金流量表 | 最新期 + 去年同期 + 年报…，共7 |
| 分红 | 最近7个年度（年度口径，不含中报列） |
| 盈利预测 | FY3、FY2、FY1 + 最新年报 + 前3年，共7 |
| 营收结构、客户供应商 | 最新期 + 去年同期 + 年报…，共7 |

列清单由探到的最新报告期按日历推算，不查接口。报告期为 03-31/06-30/09-30/12-31 四个固定日期。

列数写成常量 `PERIOD_COLUMNS = 7`，改一个数就能加深历史。

## 三、板块清单

九个板块。每个板块一个固定场景名，`fetch_scene` 直接调用；`report` 命令内部串起来。

| 板块 | 场景名 | 数据来源 | 单位 | 列数 |
|---|---|---|---|---|
| 工商信息 | 工商信息（已有） | `ths_*_stock` 公司资料族 | 原样 | 单条纵表 |
| 十大股东 | 十大股东（已有） | 现有场景 | 股数原值、比例2位 | 最新期 |
| IPO信息 | IPO信息（新） | `ths_ipo_*` 族 + 行情 | 股本万股、价元、市值亿元2位、募资万元 | 发行时 vs 最新 两列 |
| 股价行情 | 历史行情（已有，加总市值） | `ths_close_price_stock` 106 + `ths_market_value_stock` | 元、亿元 | 日线 |
| 分红 | 分红（新） | `ths_annual_accum_divid_ann_stock` 等 | 万元整数 | 7个年度 |
| 财报摘要 | 从三表取 | 三表场景 | 亿元2位 | 7列 |
| 营收结构 | 营收结构（新） | `ths_moc_project_*` 族 + `ths_main_*` 族 | 万元整数、比率1位 | 7列 |
| 盈利预测与估值 | 盈利预测（新） | `ths_fore_*` 族 + 估值族 | 万元整数、比率2位 | 7列 |
| 三表 | 三表现有场景扩展 | 现有场景 | 万元整数 | 7列 |

### 3.1 IPO信息表

沿用中际旭创那份的对照结构，发行时与最新并列：

| 项目 | 发行时 | 最新 |
|---|---|---|
| 总股本（万股） | `ths_total_shares_after_ipo_ld_stock` | `ths_total_shares_stock` |
| 股价（元） | `ths_ipo_price_stock` | `ths_close_price_stock(…,105)` 后复权 |
| 市值（亿元） | 发行价 × 发行后总股本 | `ths_close_price_stock(…,100)` × 最新总股本 |
| 市盈率（倍） | `ths_ipo_pe_dlt_stock` | `ths_pe_ttm_stock(…,100)` |
| 市净率（倍） | `ths_ipo_pb_stock` | `ths_pb_stock(…,108)` |

表下补一行募资：总额 `ths_ipo_rc_stock`、净额 `ths_ipo_actual_rc_stock`、发行费用 `ipo_fee`、上市日期 `ths_ipo_date_stock`。

### 3.2 营收结构三块

分产品、分地区、客户供应商集中度。分行业不在需求内，公式已记录，暂不实现。

| 块 | 公式 | 行 |
|---|---|---|
| 分产品 | `ths_moc_project_name_product_stock(代码,日期,序号)`、`_income_product_`、`_profit_product_` | 每项4行：收入、收入占比、毛利率、毛利占比 |
| 分地区 | 同上，后缀 `_district_stock` | 同上 |
| 客户供应商 | `ths_main_customer_sales_amt_ratio_stock`、`ths_main_customer_ratio_stock`、`ths_main_customer_name_stock`，供应商同族 | 6行 |

序号从1开始递增，取到名称为空或为 `-` 为止，上限10项。占比与毛利率本地算，用该期营业总收入与总毛利（营业总收入减营业成本）作分母。

客户供应商占比公式返回的是百分数数值（如 31.98），除以100转小数。

### 3.3 盈利预测表

沿用 xlsx 盈利预测页的行结构：

营业收入均值、营收增速、归母净利润均值、利润增速、总市值、市盈率、市销率、市净率、市现率、预测机构数。

三列预测年份取最新年报年份加1、加2、加3；四列历史取最新年报及其前三年。总市值历史列用年末日期取 `ths_market_value_stock`，预测列留空。PE/PS 未来列用当前总市值除以预测值，历史列用 `ths_pe_ttm_stock`、`ths_ps_ttm_stock` 等直接取。

### 3.4 分红表

四行：现金分红总额、股票回购总额（分红含回购减现金分红）、现金分红及回购、归母净利润。7个年度列，年度归母净利润从三表年报期取。

## 四、命令结构

### 4.1 单板块命令

不新增命令。每个板块就是一个 `fetch_scene` 场景，用法不变：

```
{"cmd":"fetch_scene","scene":"分红","code":"002796.SZ"}
```

新增场景七个：IPO信息、分红、分产品、分地区、客户供应商、盈利预测、历史估值。
扩展场景：三表支持多报告期并加科目分组、历史行情加总市值列。

### 4.2 一键命令

新增 `report`：

```
{"cmd":"report","code":"002796.SZ","output":"D:\\...\\导出目录","company":"世嘉科技"}
```

`company` 可省略，从工商信息取简称。`output` 为目录，不存在则创建。另有可选 `end_date`（数据截止交易日）、`chart_start`（行情起点）、`events`（事件CSV路径）。

内部顺序：

1. 探最新报告期
2. 按 2.2 推算7期列
3. 逐板块取数（每个板块一次 Excel 提交，三表把7期展开在同一个矩阵里）
4. 单位换算与标签生成
5. 调绘图出两张 PNG
6. 组装 Markdown
7. 落盘

### 4.3 多报告期取数

现有 `fetch_scene` 只接单个 `report_date`。改为接受 `report_dates` 列表，在同一个公式矩阵里按报告期展开为行（复用 `dims.date_range` 那套展开机制），一次提交取回全部期。返回长表，每期一行。

长表落CSV，Markdown里透视成7列宽表。

## 五、处理规则

### 5.1 单位

| 场景 | 单位 | 小数位 |
|---|---|---|
| 财报摘要 | 亿元 | 2 |
| 三表附录、营收结构、分红、盈利预测金额 | 万元 | 0 |
| 总市值、发行后市值 | 亿元 | 2 |
| 各类比率、占比 | 百分数 | 1或2，按表定 |
| 股本 | 万股 | 0 |
| 股价 | 元 | 2 |

换算在报告层做，CSV保留原始元值，方便对数。

### 5.2 三表科目顺序与分组

场景JSON的字段顺序已经是报表标准顺序（货币资金、结算备付金…流动资产），不需要重排。要补的是分组小标题：

| 表 | 分组 |
|---|---|
| 资产负债表 | 流动资产、非流动资产、流动负债、非流动负债、所有者权益 |
| 利润表 | 收入与成本、期间费用、其他损益、利润与每股 |
| 现金流量表 | 经营活动、投资活动、筹资活动、现金净变动 |

分组在场景JSON里给每个字段加 `group` 键，报告层按 group 切段输出小标题。

### 5.3 缺数据与脏值

- 科目全零或空：跳过该行，不占位
- 整块无数据：留小节标题并标「（本板块未取到数据，待补）」
- 探测失败：明确报错，不静默出空表

## 七、已定事项

按用户 2026-11-25 需求确定，不再讨论：

| 事项 | 定论 |
|---|---|
| 报告期列数 | 7列 |
| 工商信息 | 全部能拿到的字段，按语义分组呈现 |
| 分红表 | 沿用中际旭创正文格式：现金分红总额、股票回购总额、现金分红及回购、归母净利润，年度列 |
| 分行业 | 不做，需求只提分产品、分地区、客户供应商集中度三块 |
| 十大股东 | 并入「一、公司基本信息」下，不单列章节 |
| 行情图 | 用户定稿改为一张双轴图：左轴总市值、右轴前复权收盘价；有事件CSV则标注，没有则不画 |
| 预测年份 | 按年报推：最新年报未出则预测当年，已出则预测次年及后两年（2026年报未出则预测2026年，出了则预测2027年） |
| 单季表 | 不做，只要累计口径三表 |
| 衍生指标 | 不做（同比增长率、ROE、毛利率等留后续） |

## 八、实施步骤与验收

分四步，每步跑通再下一步：

1. 多报告期取数：扩展三表场景，验证某公司7期数据齐全、期次标签正确
2. 新场景七个：IPO信息、分红、分产品、分地区、客户供应商、盈利预测、历史估值，逐个用真实公司验证公式返回值
3. 报告层重写：单位换算、分组、7列透视、章节拼装
4. `report` 一键命令：串起来，出一份完整报告
