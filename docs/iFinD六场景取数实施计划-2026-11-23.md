## 二、五步实施

按依赖顺序排列，前一步的产物是后一步的输入。

### 第一步：修搜索排序

现状问题：搜索「净资产」，第一条返回「归属于母公司所有者权益合计」，因该条别名为「归母净资产」，包含「净资产」三字。AI若取第一条会拿到2331.06亿元，而用户要的合并口径是2420.11亿元，差89.05亿元即少数股东权益。

改法：结果按匹配强度排序，顺序为

| 优先级 | 匹配类型 | 例 |
|---|---|---|
| 1 | 指标码完全相同 | 传 `ths_total_owner_equity_stock` |
| 2 | 正式名称完全相同 | 传「所有者权益合计」 |
| 3 | 别名完全相同 | 传「净资产」 |
| 4 | 正式名称包含 | 传「所有者权益」 |
| 5 | 别名包含 | 传「净资」 |
| 6 | 定义正文包含 | 靠后，并标注仅为定义命中 |

同时补两项：

- 返回每条记录是数值型还是文字型。现在不返回，AI不知道文字字段要走文本通道。
- 结果分页，不再直接截断。现在命中19条时只能看到前5条，无法翻看。

验收：搜「净资产」第一条为「所有者权益合计」；搜「归母净资产」第一条为「归属于母公司所有者权益合计」；搜「总资产」第一条为「资产总计」；每条结果含数值/文字标识；limit与offset生效。

### 第二步：补录十大股东七个指标

七个指标实测全部可用，但均未入库。

| 指标 | 指标码 | 参数格式 |
|---|---|---|
| 股东名称 | `ths_holder_name_stock` | 代码, 报告期八位, 排名 |
| 股东性质 | `ths_holder_nature_stock` | 同上 |
| 持股数 | `ths_holder_held_num_stock` | 同上 |
| 限售股数 | `ths_holder_held_ls_num_stock` | 同上 |
| 质押股数 | `ths_ma_holder_pledge_stock` | 同上 |
| 冻结股数 | `ths_holder_freeze_stock` | 同上 |
| 持股比例 | `ths_holder_held_ratio_stock` | 同上 |

实测证据：

- 贵州茅台2024-12-31：名称第1名「中国贵州茅台酒厂(集团)有限责任公司」持股679211576股、比例54.07%，第2名「香港中央结算有限公司」77511622股、6.17%，与年报一致。
- 参数顺序经实测确认：代码在前，报告期为八位字符串，排名为独立第三个参数。此前把报告期与排名合并为一个字符串，导致十个排名返回同一名字，已排除。
- 质押与冻结三个字段在茅台上均返回0，属公司实际无此情形。换公司验证确认参数正确：比亚迪第三名质押62611600股、中际旭创第一名质押16520000股。
- 排名取1至10，返回十行。排名0表示前十名合计，不是单条记录，不入清单默认值。

路径按插件层级记为「股票全部指标/股东结构」。录入走 `update_verified.py` 并记correction-log，逐条带实测证据。命中率为零的字段（质押、冻结在部分公司为0）标 `verified_with_caveat` 并在notes说明零值为公司实际情况而非取数失败。

验收：查询七个指标均能命中；`lookup` 搜「十大股东」「股东」能带出这组记录；用茅台一期的七字段乘十名次共70式一次取回且为完整表格。

### 第三步：把取较大值逻辑接进程序

规则已写入科目备注，但当前取数仍要AI自己拼两个公式再比较。需在取数流程内实现：

- 字段配置支持多候选加 `pick: max`。
- 展开时每个候选各占一列，一次提交。
- 合并时取较大值；两值不同时在结果中记录选了哪个、弃掉的值是多少。
- 两值相同时不出记录，避免正常数据被冗余说明淹没。
- 两值同时为0即为0，不告警、不重试、不判断是否漏采（用户2026-11-23确认）。

验收：三类场景均取到正确值且带选择记录——贵州茅台2025-09-30（季报，单项为0应选中合计）、工商银行2024-12-31（金融公司，合计为0应选中单项）、万华化学2025-12-31（重资产，合计更全，应选中合计346.25亿元并记录弃311.12亿元）。

### 第四步：建六个场景清单

| 场景 | 内容 | 库支撑 |
|---|---|---|
| 工商信息 | 公司全称、英文名、注册资本、成立日期、法人、注册地址、办公地址、省份、地市、邮编、经营范围、主营业务、公司简介、网站、电话、所属行业、员工总数、上市日期、上市地点、上市板块、交易币种、实际控制人、董事长、总经理、董秘、财务总监 | 基本资料69条，实测19项一次取回全部有值 |
| 十大股东 | 七字段乘十名次 | 依赖第二步 |
| 历史行情 | 开高低收、成交量、成交额、总市值 | 行情与市值指标齐全 |
| 估值快照 | 市盈率、市净率、总市值、流通市值 | 齐全 |
| 三张报表 | 资产负债表155条、利润表92条、现金流量表118条 | 齐全 |
| 单季报表 | 利润表单季109条、现金流量表单季114条 | 齐全 |

场景级默认值：

- 历史行情：起2016-01-01，止为当天，前复权（复权码108，实测最新交易日与不复权同值、历史值向下调整）。
- 十大股东：默认取最近一期年报。
- 三张报表与单季报表：默认取最近4期与最近8季。

验收：六个场景各用一家真实公司跑通，字段齐全、无报错、数值与公告或既有工具可对上。

### 第五步：CSV导出

- 调用方可指定保存路径，指定则写CSV并返回路径与行数。
- 未指定且结果行数超阈值时，自动写CSV到固定目录并返回路径，避免把大结果整包塞进对话。
- 阈值实现时定，取向是对话里能读得完的小结果不落盘。
- 多代码批量取数时，文件名带代码以区分。

验收：指定路径能生成CSV且内容与对话返回值一致；不指定路径的大结果自动落盘并返回可打开的文件路径；CSV用Excel直接打开中文不乱码。

## 三、实施顺序与依赖

```mermaid
flowchart LR
    A["一 修搜索排序"] --> B["二 补股东指标"]
    B --> C["三 接取大值逻辑"]
    C --> D["四 建六个清单"]
    D --> E["五 CSV导出"]
```

第一步先行，因为建清单时要靠搜索确认字段名与正式名称。第二步先于第四步，否则十大股东清单缺七个指标无法成立。

## 四、每步的验收方式

每一步完成后做真实取数验证，不以代码写完为准。验证样本用公开可比对的公司：贵州茅台（白酒）、工商银行（金融）、比亚迪与万华化学（重资产）、中际旭创（制造业）。

## 五、明确不做

- 衍生指标（毛利率、ROE、资产负债率、同比增长率）：用户决定先不管。
- 分产品、分地区收入与客户供应商集中度：已验证库无对应指标，需iFinD表格型接口，与公式矩阵不同形态，继续走market-data。
- 区间行情指标：已验证库零条，需用户提供插件原文，且当前单公司长历史需求可用逐日方式满足。
- 汇率、期货、期权、基金等其他资产类别的场景：不在本次范围。
