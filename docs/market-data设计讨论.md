# market-data MCP 设计讨论文档

> 2026-08 讨论定稿。本文档是 market_data MCP 的设计共识，实现按此执行。
> 对应仓库：本仓库（与公告 MCP 同仓库，独立包 `market_data_mcp`）。

## 一、定位

**三市场（A股/港股/美股）行情与基本面数据获取工具**，与公告阅读 MCP 并列互补：

| | 公告 MCP（已有） | market-data MCP（本设计） |
|---|---|---|
| 数据类型 | 公告/提交文档（非结构化） | 行情/财报/指标/概况（结构化） |
| 数据源 | 东财公告接口 + SEC EDGAR | AKShare（东财→新浪→腾讯→可扩展） |
| 消费方式 | 查询/阅读/搜索 | 下载到本地缓存 + 返回元信息 |

## 二、核心设计决策

### 1. 统一通道：下载到缓存，返回元信息

**所有工具**（不分数据大小）都走同一条通道：

```
调用工具 → 检查本地缓存 → 够用则直接读缓存返回元信息
                        → 不够则拉新数据入缓存 → 返回元信息
```

- **不返回数据本体**，只返回元信息（成功/失败/文件路径/新增内容/数据范围/总量）
- AI 用文件工具读缓存文件；脚本用脚本读缓存文件
- 工具不做汇总文档——汇总由用户自己的脚本做

### 2. 缓存：本地 JSON + 全量 + 增量

- 缓存存 `cache/{代码}/` 下，按数据维度分文件：
  ```
  cache/300476.SZ/
  ├── quote_daily_qfq.json      # 行情（各 adjust×period 一个文件）
  ├── financial_income.json     # 利润表
  ├── financial_balance.json    # 资产负债表
  ├── financial_cash_flow.json  # 现金流量表
  ├── ratios.json               # 财务指标
  └── profile.json              # 概况/分红/盈利预测
  ```
- 首次建档 = 全量；之后 = 增量追加（行情拉 last_date 之后，财报拉新报告期）
- 格式：JSON，`{meta, items}` 骨架：
  ```json
  {
    "meta": {"code", "market", "data_type", "source", "updated_at", "date_range", "shape"},
    "items": [...]
  }
  ```
- **增量失败 = 缓存未更新**：直接返回"缓存获取失败，请重试"，不记录失败过程（简单策略）

### 3. 行情：字段为中心，来源可插拔

- **以所需字段为基本单位，不以来源为基本单位**：
  - 每个字段有自己的来源优先级链（如 close: 东财→新浪→腾讯→iFinD→...）
  - 链上任何一个源拿到即填入缓存
  - 全链失败才标注该字段缺失
- 数据源可随时插拔替换：东财、新浪、腾讯、iFinD、第三方 API 都是可替换的实现
- **字段的获取方式分两类**：
  1. **直接获取**：数据源返回该字段（close/volume/换手率...）
  2. **派生计算**：由其他字段组合算出（总市值=总股本×不复权收盘价、未来 PE/PB/自由流通市值同理），底层仍是直接获取的字段
- **新字段接入统一流程**：定义字段名 + 来源链（或计算式）→ 链上任一环节成功即有值 → 全链失败标注缺失 → 某字段不稳定只调该字段的来源优先级，不动其他字段
- **不处理字段差异**：收盘价在哪拿都是收盘价。流通股本东财没有就跳过东财，振幅新浪没有就跳过新浪
- 核心组打包：开/高/低/收/量/额 打包一次请求（东财/新浪均一次返回）
- 衍生字段（换手率/振幅/涨跌幅/流通股本）各自走自己的来源链
- 首次全量：上市以来所有交易日；start/end 只是查询视图
- 市值：总股本 × 不复权收盘价（估算，季度级精度），标注为估算值

### 4. 财报：统一形状，不改科目名

- **三市场三表统一为同一形状**（长表）：
  ```
  items: [{report_date, item_name, amount, source}, ...]
  ```
- **科目名不改**：港股返回什么科目就叫什么科目（A股宽表内部转长表，科目名原样保留）
- 不做跨市场科目映射（那是 iFinD 的坑，工具不做猜测性转换；跨市场比较由 AI/用户脚本处理）
- 三表按报告期增量：首次全量，之后拉新报告期

### 5. 指标/概况

- 财务指标（ROE/毛利率等）：原始返回，东财列名原样（如 ROEJQ=加权ROE）
- 概况/分红/盈利预测：一个文件，sections 可选（profile/dividends/forecast）

### 6. 强制市场后缀

- **代码必须带后缀**：`300476.SZ` / `600519.SH` / `900901.SH`(沪B) / `200725.SZ`(深B) / `00700.HK` / `AAPL.US`
- 脚本按后缀路由市场，**禁止按数字位数/开头猜测**（"脚本不猜测，AI 负责灵活"）
- 不带后缀 → 报错提示
- 公告 MCP 暂不改（有下游依赖），本工具强制执行

### 7. 限流策略（简单）

1. **先查缓存**：缓存够用（覆盖请求范围）→ 直接读，零网络
2. **不够再拉**：拉新数据入缓存 → 从缓存返回
3. **失败即重试**：失败 = 缓存未更新 → 告诉 AI "缓存获取失败，请重试"，AI 重试时自动跳过已完成部分
4. 回退链：东财→新浪→腾讯→（可扩展 iFinD/第三方）

## 三、工具面（4 工具）

| 工具 | 参数 | 缓存文件 | 返回元信息 |
|---|---|---|---|
| get_quote | code, start, end, adjust(qfq/hfq/none), period(daily/weekly/monthly), fields[] | quote_{period}_{adjust}.json | ok/path/新增/范围/总量/缺失字段 |
| get_financial_statements | code, periods[], statements[] | financial_{income/balance/cash_flow}.json | 同上 |
| get_financial_ratios | code, periods[] | ratios.json | 同上 |
| get_company_profile | code, sections[] | profile.json | 同上 |

返回元信息统一格式：
```json
{
  "ok": true,
  "cached": true/false,
  "path": "cache/300476.SZ/quote_daily_qfq.json",
  "new_items": 0,
  "date_range": "2017-01-01~2026-08-05",
  "total_items": 2312,
  "missing_fields": [],
  "notes": []
}
```

## 四、明确不做（边界）

- ❌ 不做汇总文档工具（用户自己写脚本汇总）
- ❌ 不做跨市场科目映射（科目名原样）
- ❌ 不返回数据本体（只返回元信息，数据在缓存文件）
- ❌ 不做实时行情（只做历史日/周/月线）
- ❌ 分钟级数据
