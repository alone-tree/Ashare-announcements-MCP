# market-data MCP 设计讨论文档

> 2026-08 讨论定稿。本文档是 market_data MCP 的设计共识，实现按此执行。
> 对应仓库：本仓库（与公告 MCP 同仓库，独立包 `market_data_mcp`）。

## 一、定位

**三市场（A股/港股/美股）行情与基本面数据获取工具**，与公告阅读 MCP 并列互补：

| | 公告 MCP（已有） | market-data MCP（本设计） |
|---|---|---|
| 数据类型 | 公告/提交文档（非结构化） | 行情/财报/指标/概况（结构化） |
| 数据源 | 东财公告接口 + SEC EDGAR | AKShare（东财→新浪→腾讯→可扩展） |
| 消费方式 | 查询/阅读/搜索 | 下载到本地缓存 + 返回元信息 |

## 二、核心设计决策

### 1. 统一通道：下载到缓存，返回元信息

**所有工具**（不分数据大小）都走同一条通道：

```
调用工具 → 检查本地缓存 → 够用则直接读缓存返回元信息
                        → 不够则拉新数据入缓存 → 返回元信息
```

- **不返回数据本体**，只返回元信息（成功/失败/文件路径/新增内容/数据范围/总量）
- AI 用文件工具读缓存文件；脚本用脚本读缓存文件
- 工具不做汇总文档——汇总由用户自己的脚本做

### 2. 缓存：本地 JSON + 全量 + 增量

- 缓存存 `cache/{代码}/` 下，按数据维度分文件：
  ```
  cache/300476.SZ/
  ├── quote_daily_qfq.json      # 行情（各 adjust×period 一个文件）
  ├── financial_income.json     # 利润表
  ├── financial_balance.json    # 资产负债表
  ├── financial_cash_flow.json  # 现金流量表
  ├── ratios.json               # 财务指标
  └── profile.json              # 概况/分红/盈利预测
  ```
- 首次建档 = 全量；之后 = 增量追加（行情拉 last_date 之后，财报拉新报告期）
- 格式：JSON，`{meta, items}` 骨架：
  ```json
  {
    "meta": {"code", "market", "data_type", "source", "updated_at", "date_range", "shape"},
    "items": [...]
  }
  ```
- **增量失败 = 缓存未更新**：直接返回"缓存获取失败，请重试"，不记录失败过程（简单策略）

### 3. 行情：字段为中心，来源可插拔

- **以所需字段为基本单位，不以来源为基本单位**：
  - 每个字段有自己的来源优先级链（如 close: 东财→新浪→腾讯→iFinD→...）
  - 链上任何一个源拿到即填入缓存
  - 全链失败才标注该字段缺失
- 数据源可随时插拔替换：东财、新浪、腾讯、iFinD、第三方 API 都是可替换的实现
- **字段的获取方式分两类**：
  1. **直接获取**：数据源返回该字段（close/volume/换手率...）
  2. **派生计算**：由其他字段组合算出（总市值=总股本×不复权收盘价、未来 PE/PB/自由流通市值同理），底层仍是直接获取的字段
- **新字段接入统一流程**：定义字段名 + 来源链（或计算式）→ 链上任一环节成功即有值 → 全链失败标注缺失 → 某字段不稳定只调该字段的来源优先级，不动其他字段
- **不处理字段差异**：收盘价在哪拿都是收盘价。流通股本东财没有就跳过东财，振幅新浪没有就跳过新浪
- 核心组打包：开/高/低/收/量/额 打包一次请求（东财/新浪均一次返回）
- 衍生字段（换手率/振幅/涨跌幅/流通股本）各自走自己的来源链
- 首次全量：上市以来所有交易日；start/end 只是查询视图
- 市值：总股本 × 不复权收盘价（估算，季度级精度），标注为估算值

#### 3.1 行情字段决策（2026-08-07 讨论定稿）

**核心组 = OHLCV + amount，一次请求打包获取，组级 fallback**（任一字段失败 → 整组降级到下一个源，不逐字段拆；理由：各源均一次返回整组，且东财不会出现"有开盘无收盘"的残缺情况）。复权维度由请求参数承载，三份独立缓存文件。

**派生字段（振幅/涨跌幅/涨跌额/换手率）现阶段不获取**，用不上；后续需要时按"字段表"流程增加。

**复权方案（定稿）**：直接向源请求 qfq/hfq/不复权 三份，缓存三个文件（数据量冗余可接受，不引入复权因子本地计算层——因子源与口径不一致的坑比存储冗余更麻烦）。

**腾讯源 volume 单位问题（实测 2026-08-07）**：

| 板块 | 样本 | 腾讯返回 | 新浪(股) | 关系 |
|---|---|---|---|---|
| 沪主板 | 600519 | 36147 | 3,614,686 | 手数 round(股/100) |
| 创业板 | 300476 | 257337 | 25,733,659 | 手数 round(股/100) |
| 科创板 | 688981 | 65,437,562 | 65,437,562 | 股数原样返回 |

结论：腾讯 volume/amount 单位不统一（主板/创业板按手、科创板按股，且手数为 round 后精度损失），**腾讯不参与 volume/amount 的 fallback**；仅保留在 OHLC 价格链（实测价格与新浪一致，可靠）。

**行情字段表（核心组，8 字段）**：

| 字段 | 含义 | A股来源链 | 港股来源链 | 美股来源链 | 备注 |
|---|---|---|---|---|---|
| date | 交易日 | 东财→新浪→腾讯 | 东财→新浪 | 东财→新浪 | |
| open | 开盘价 | 东财→新浪→腾讯 | 东财→新浪 | 东财→新浪 | |
| high | 最高价 | 东财→新浪→腾讯 | 东财→新浪 | 东财→新浪 | |
| low | 最低价 | 东财→新浪→腾讯 | 东财→新浪 | 东财→新浪 | |
| close | 收盘价 | 东财→新浪→腾讯 | 东财→新浪 | 东财→新浪 | |
| volume | 成交量(股) | 东财→新浪 | 东财→新浪 | 东财→新浪 | 腾讯剔除（单位不统一） |
| amount | 成交额 | 东财→新浪 | 东财→新浪 | 东财 | 美股新浪无 amount → 东财挂则缺失 |
| total_market_cap | 总市值 | 派生：报告期股本×不复权收盘 | 派生：历史股本×不复权收盘 | 派生：历史股本×不复权收盘 | 第一批核心字段，与收盘价同级 |

**总市值（第一批核心字段，2026-08-07 用户确认）**：
- 计算式：当日总股本 × 当日不复权收盘价（逐日对齐 K 线，非当前快照值）
- 股本来源链：A股 = 资产负债表报告期股本（东财，季度级，merge_asof 向后匹配）；港股/美股 = **yfinance 资产负债表 Common Stock Shares Outstanding**（年报多期，新增数据源）
- 港股财务指标接口只有最新股本一行（不可用）；美股免费接口（东财财务指标/资产负债表、雪球、百度）均无历史股本
- 新浪单股实时接口有当前总市值/总股本，但仅当前值，只可作"最新市值"参考，不作为历史市值来源
- 新增依赖：系统 Python 3.13 环境需安装 yfinance（与行情源并列的独立来源，参与股本链 fallback）

周/月线：只存日线，周/月线由日线现算，不落盘（聚合规则见 providers/_common.py resample_ohlcv）。

| 来源 | 数据形态 | 覆盖 | 精度 | 实测样本（0700.HK） |

**美股**：

| 来源 | 数据形态 | 覆盖 | 精度 | 实测样本（AAPL） |
|---|---|---|---|---|
| 新浪单股实时 `gb_aapl` [19] | 当前值 | 仅最新 | 时点 | 14,594,180,632 |

| yfinance 季度资产负债表 | 季度报告期 | 近 2 年（7 期） | 季度 | — |
| yfinance `get_shares_full(start,end)` | 事件点序列 | 2015 底起 ~10 年 | 事件级 | 420 点，2025 起更密（89 点/年） |

**探测结论**：
- yfinance 是港股/美股历史股本的唯一免费来源；上限约 10 年（2015 底起），传 start=1980 无效，Yahoo 只保留约 10 年
- yfinance 必须走代理（127.0.0.1:17891），直连被 Yahoo 限流（YFRateLimitError）；与东财/新浪（清代理直连）相反，实现时需为 yfinance 单独处理代理
- yfinance 三档互补：年度表（5 期打底）、季度表（近 2 年 7 期）、get_shares_full（10 年事件点，最细，有重复日期需去重）
- 港股存在库存股：`Ordinary Shares Number` = `Share Issued` − `Treasury Shares Number`（腾讯 2025: 9,032,821,385 vs 9,120,235,999，差 87,414,614）
- 交叉验证：yfinance 2025 值 ↔ 新浪/东财当前值，差异即后续回购，自洽
- 2015 年之前的股本：yfinance 不可得；可用来源仅"当前值近似"或"公告解析"（SEC 10-K / 港股年报，成本高）

#### 3.4 实现决策（2026-08-07 用户定稿）

**仓库定位**：market-data MCP 与公告 MCP **同仓库**（Ashare-announcements-MCP，独立包 `market_data_mcp`），不拆独立仓库（2026-08-08 用户确认）。现有实现代码作参考，按本文档重构。

**数据源优先级（行情）**：iFinD Python SDK（第一）→ AKShare 东财 → AKShare 新浪。美股后复权新浪不支持（实测 TypeError），链为 iFinD → 东财。

**iFinD 账号配置**：config 中填账号密码（支持多账号），有则使用、无则自动跳过该源；沿用 skill 多账号容灾模式（登录后小查询验证可用性）。

**复权口径（用户定稿）**：
- 后复权：直接来自提供商（iFinD CPS:3 / 东财 / 新浪 hfq），**不做任何调整**
- 前复权：**计算得出，不缓存**。`前复权(t) = 后复权(t) × (最新不复权收盘 / 最新后复权收盘)`，除权因子取同一交易日（日期对齐），随分红自动更新
- 缓存只存：不复权（raw）+ 后复权（hfq）两个文件，均为静态历史永不过期

**外部代码格式（统一标准，程序只认后缀路由市场）**：
- A股：`300476.SZ`、`600519.SH`、`832000.BJ`（.sz/.sh/.bj）
- B股：`900901.SH`（沪B）、`200725.SZ`（深B）——**已验证与 A股完全同渠道，无需任何额外处理**（2026-08-07 实测：iFinD `900901.SH`/`200725.SZ` 直查 ✅；新浪 `sh900901`/`sz200725` 走 stock_zh_a_daily 同接口 ✅，数据与 iFinD 逐日一致；后复权 hfq 同样支持。路由只看 .SH/.SZ 后缀即可，不区分 A/B 股）
- 港股：`00700.HK`（带 .hk 后缀）
- 美股：`AAPL.US`（字母代码 + .us 后缀）
- **路由只看后缀，不看数字**：.sz/.sh/.bj → A股渠道、.hk → 港股、.us → 美股
- 内部按源转换：iFinD 港股需 4 位带前导零（0700.HK）、AKShare 需 5 位裸码（00700）

#### 3.3 iFinD 数据源探测结果（2026-08-07 实测，jdkgjt009 账号）

**定位变更**：iFinD Python SDK 作为行情数据**第一来源**（用户有正式账号），AKShare 降为回退。

**四市场可用性：**

| 市场 | 代码格式 | 行情(OHLCV+amount) | 市值 | 股本 |
|---|---|---|---|---|
| A股 | `300476.SZ` | ✅ 全通 | ✅ THS_DS market_value+USD | ✅ ths_total_shares_stock |
| B股 | `900901.SH`/`200725.SZ` | ✅ 全通 | — | — |
| 港股 | `0700.HK`（4位带前导零） | ✅ 全通 | ✅ THS_DS | — |
| 美股 | `AAPL.O` | ✅ OHLC+volume；amount 需 THS_BD 单点（HistoryQuotes 返回 None） | ✅ THS_DS（ths_market_value_stock 返回 0 不可用） | ❌ None（不需要，市值直接给） |

**关键接口结论：**
- `THS_HistoryQuotes`：历史行情序列，返回 **dict**（errorcode/tables[0]={thscode,time,table}），与 THS_BD/THS_DS（THSData 对象）返回类型不同
- 币种：**不传 Currency = 原始币种**（A股人民币/港股港元/美股美元）；`Currency:MHB` 反而折美元（坑）
- 复权：`CPS:1`=不复权、`CPS:2`=前复权、`CPS:3`=后复权（数字格式；THS_HF 的 forward1 字符串在此无效）
- 港股代码：`0700.HK` ✅，`700.HK`/`00700.HK` 报 -4210（与 skill 旧记录"无前导零"相反，已修正）
- 账号容灾：jdlhk001 登录 -1（不可用）、jdkgjt009 正常——沿用 skill 多账号模式
- 代理：iFinD 国内服务，清代理直连可用

**交叉验证（与 AKShare/新浪一致）：**
- A股 300476：close=189.3（8/3）= 新浪 ✓；volume=25,733,659 = 新浪 ✓；市值 USD 334.86亿 = 236.35×9.83亿股 自洽 ✓
- 港股 0700.HK：close=492.2、amount=126亿港元、市值 5700亿美元 ✓
- 美股 AAPL：close=303.42/309.38/311 与新浪实时 312.41 衔接 ✓；市值 4.54万亿 = 新浪 4.57万亿（同日汇率微差）✓

**对设计的影响：**
- 三组字段（OHLC/量额/市值）iFinD 全部直接提供，**市值不再需要 yfinance 股本链自算**（除非要求"股本×收盘"口径），官方市值更准
- 美股 amount 序列缺口：HistoryQuotes 恒 None，THS_BD 可单点取——批量取美股 amount 的序列方案待定（THS_DS 指标名待确认）
- 实现时字段表来源链改为：iFinD 第一 → AKShare（东财→新浪→腾讯）回退

### 4. 财报：统一形状，不改科目名

- **三市场三表统一为同一形状**（长表）：
  ```
  items: [{report_date, item_name, amount, source}, ...]
  ```
- **科目名不改**：港股返回什么科目就叫什么科目（A股宽表内部转长表，科目名原样保留）
- 不做跨市场科目映射（那是 iFinD 的坑，工具不做猜测性转换；跨市场比较由 AI/用户脚本处理）
- 三表按报告期增量：首次全量，之后拉新报告期

### 5. 指标/概况

- 财务指标（ROE/毛利率等）：原始返回，东财列名原样（如 ROEJQ=加权ROE）
- 概况/分红/盈利预测：一个文件，sections 可选（profile/dividends/forecast）

### 6. 强制市场后缀

- **代码必须带后缀**：`300476.SZ` / `600519.SH` / `900901.SH`(沪B) / `200725.SZ`(深B) / `00700.HK` / `AAPL.US`
- 脚本按后缀路由市场，**禁止按数字位数/开头猜测**（"脚本不猜测，AI 负责灵活"）
- 不带后缀 → 报错提示
- 公告 MCP 暂不改（有下游依赖），本工具强制执行

### 7. 限流策略（简单）

1. **先查缓存**：缓存够用（覆盖请求范围）→ 直接读，零网络
2. **不够再拉**：拉新数据入缓存 → 从缓存返回
3. **失败即重试**：失败 = 缓存未更新 → 告诉 AI "缓存获取失败，请重试"，AI 重试时自动跳过已完成部分
4. 回退链：东财→新浪→腾讯→（可扩展 iFinD/第三方）

## 三、工具面（4 工具）

| 工具 | 参数 | 缓存文件 | 返回元信息 |
|---|---|---|---|
| get_quote | code, start, end, adjust(qfq/hfq/none), period(daily/weekly/monthly), fields[] | quote_{period}_{adjust}.json | ok/path/新增/范围/总量/缺失字段 |
| get_financial_statements | code, periods[], statements[] | financial_{income/balance/cash_flow}.json | 同上 |

```json
  "new_items": 0,
  "date_range": "2017-01-01~2026-08-05",
  "total_items": 2312,
  "missing_fields": [],
  "notes": []
}
```

## 四、明确不做（边界）

- ❌ 不做汇总文档工具（用户自己写脚本汇总）
- ❌ 不做跨市场科目映射（科目名原样）
- ❌ 不返回数据本体（只返回元信息，数据在缓存文件）
- ❌ 不做实时行情（只做历史日/周/月线）
- ❌ 分钟级数据
