# 公告阅读产品设计

## 1. 产品目标

让 AI 面对短公告、长文档、复杂表格和扫描件时，都能自然完成“先判断文档，再定位内容，最后精读原文”，同时满足两个约束：

1. 不把整份年报或招股书塞进上下文。
2. 不因为分块而让 AI 失去页码、表格结构或全文覆盖能力。

工具不直接生成摘要或投资结论，只提供可追溯到 PDF 页码的可靠阅读材料。

## 2. 实测样本

本轮使用东方雨虹不同年份、不同格式的真实公告验证。

| 类型 | 公告编号 | 页数 | 原生文本 | 关键特征 |
|---|---|---:|---:|---|
| 短公告 | `AN202607011826634266` | 3 | 1,820 字符 | 纯文字，适合直接阅读 |
| 年报 | `AN202604161821273802` | 312 | 301,388 字符 | 长文、目录、密集财务表格 |
| 审计报告 | `AN202604161821273797` | 158 | 147,682 字符 | 原生文本与扫描财务报表混合，13 个扫描页 |
| 招股书 | `AN201202270004245985` | 254 | 220,775 字符 | 超长文、章节和大型表格 |
| 旧审计报告 | `AN201202270004245986` | 80 | 62,313 字符 | 旧版 PDF，文字与表格混排 |

混合审计报告的扫描页集中在第 9-16 页和第 154-158 页。样本同时做了 PDF 页面渲染检查，确认短公告正文、年报表格、扫描盖章报表、原生文字页和招股书大表格均属于真实格式差异。

## 3. 核心判断

单一 PDF 文本提取器无法同时解决所有格式。最有效的方案不是把所有页面都 OCR，而是建立分层管线：

1. **快速索引层**：PyMuPDF 提取所有页面的原生文本、图片数量、标题线索和目录。
2. **格式判断层**：低文本且含图片的页面标记为疑似扫描页。
3. **结构化阅读层**：普通页由 PyMuPDF4LLM 转为 Markdown，尽量保留表格。
4. **OCR 回退层**：只有扫描页在检索或阅读需要时才调用 RapidOCR。
5. **持久缓存层**：原生文本、Markdown 和 OCR 结果写入逐页索引，避免重复计算。

这比“全量 OCR”更快，也避免 OCR 破坏原本可准确提取的数字和表格。

RapidOCR/ONNX 直接运行在 MCP 服务进程中会出现无响应，因此 OCR 被隔离到独立工作进程，并关闭继承的 stdin，避免占用 MCP 的 stdio 协议管道。多个扫描页在同一个工作进程内批量识别，减少模型重复初始化。

## 4. AI 阅读流程

### 4.1 短公告

AI 直接调用 `read_announcement(start_page=1)`。工具通常一次返回全部页面，并保留页码。

### 4.2 年报、招股书等长公告

1. 调用 `inspect_announcement`，了解页数、目录、扫描页和文档类型。
2. 根据问题调用 `search_announcement`，在完整文档索引中找到相关页。
3. 对命中页及相邻页调用 `read_announcement`，获取完整上下文和表格。
4. 若需要顺序通读，使用返回的 `next_page` 继续，直到 `is_last_chunk=true`。

完整索引保证“可查全”，页段返回保证“不撑爆上下文”。AI 不必盲目读取 300 页，也不会只看到预先截断的前若干页。

### 4.3 扫描件

`inspect_announcement` 先暴露扫描页范围。`search_announcement` 默认让扫描页参与检索，但每次最多识别 3 页，避免超过 MCP 的 30 秒调用时限；返回 `search_complete=false` 时，AI 用相同参数继续调用，直至索引完整。`read_announcement` 读取扫描页时自动 OCR。识别结果保留页码并写入缓存。

### 4.4 表格

正常 PDF 表格优先转换为 Markdown 表格。扫描表格按文字坐标恢复行，并用竖线分隔同一行单元格。后者适合 AI 理解字段和值，但不承诺完全还原合并单元格和视觉排版。

## 5. 上下文控制

- 默认单次软上限为 12,000 字符。
- 只按完整页面返回，不在页面中间截断，避免数字、表头和注释被拆开。
- 返回 `pages_returned`、每页提取方式和 `next_page`，AI 可稳定续读。
- 全文检索只返回短片段和页码，真正分析前再读取命中页。
- 长文索引保留完整目录，但体检只返回最多 30 条一级目录，并同时返回完整目录项数，防止目录自身占用过多上下文。
- 扫描页 OCR 单次最多处理 3 页，以适配能力库 relay 的 30 秒工具调用时限。

`max_chars` 是软上限：当单页本身超过限制时，仍返回该完整页面。这是“上下文可控”和“页面语义完整”之间的明确取舍。

## 6. 工具职责

| 工具 | 负责 | 不负责 |
|---|---|---|
| `inspect_announcement` | 文档画像、扫描页识别、目录 | OCR、摘要 |
| `search_announcement` | 全文关键词定位、OCR 扫描页检索 | 语义向量检索、结论生成 |
| `read_announcement` | 完整页、Markdown 表格、OCR | 整篇长文一次性返回 |

工具刻意保持确定性。主题总结、跨页推理和投资判断交给调用它的 AI 完成。

## 7. 已知边界

- OCR 对低分辨率、倾斜、手写或复杂合并单元格可能出错，AI 应以页码为依据核对上下文。
- 关键词检索是轻量 OR/AND 逻辑，不处理同义词和语义相似度。
- PDF 可见页码与文档印刷页码可能不同；工具统一使用 PDF 从 1 开始的可见页序号。
- PyMuPDF4LLM 对无边框表格的还原效果取决于 PDF 内部结构。

## 8. 验收标准

- 短公告可一次完整返回。
- 300 页以上年报可在不全文返回的情况下检索并读取目标页。
- 原生财务表格输出为 Markdown，保留主要行列关系。
- 混合 PDF 能识别扫描页，OCR 后可搜索和阅读扫描页内容。
- 每次返回包含真实 PDF 页码，长文可通过 `next_page` 无缝续读。
- export 后能力库 reload 成功，三个阅读工具均可通过能力库实际调用。

## 9. 本轮验证结果

| 验证项 | 实际结果 |
|---|---|
| 公告列表默认查询 | 完整档案 3,053 条，共 62 页；第 1、2 页均返回 50 条且边界无重复 |
| 312 页年报体检 | 识别为 `long_structured`；完整目录 454 项，仅返回 8 条一级目录 |
| 年报 AND 检索 | `营业收入 AND 净利润` 命中 6 页 |
| 招股书检索 | `募集资金` 命中 24 页 |
| 3 页短公告 | 一次返回 3 页、1,958 字符，`is_last_chunk=true` |
| 原生表格 | 年报第 5 页输出 Markdown 表格，`table_detected=true` |
| 混合扫描报告 | 识别第 9-16、154-158 页共 13 个扫描页 |
| 扫描表格 OCR | 第 9 页返回 2,260 字符，保留资产负债表主要行列和金额 |
| 扫描全文索引 | 余下 12 页分 4 次完成，单次 3 页，最终 `search_complete=true` |
| 旧版审计报告 | 80 页均可建立原生文本索引并按页读取 |

以上结果均来自 export 用户版；公告查询、体检、检索、Markdown 表格和 OCR 读取均通过能力库 reload 后的真实 MCP 调用验证。
