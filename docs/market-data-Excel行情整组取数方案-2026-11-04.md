## 一、已确认方向

1. 当前只打磨 iFinD Excel 行情通道。请求缺失日期区间时整组获取行情字段，再按现有流程保存本地缓存、读取缓存并进行加工；公司/证券两层字段的取数安排见§5.4，输出仍按调用方请求的变量选择，避免日后每增加一个变量就重新请求。
2. 本轮范围按 XMind 内地 Excel 分支收敛为高开低收、均价、成交量、成交额、换手率及公司/证券总股本、总市值；公司/证券两层的流通股本和流通市值全部移出本轮取数、缓存及输出设计，换手率使用上游直取值。PE TTM、PB、股息率作为后续扩展，不据此提前改财报和公司信息模块。
3. 复权统一选择 iFinD 默认后复权。用户此前选择的“现金分红口径”由本次决定覆盖；不额外指定现金分红或分红再投，也不把同一参数编号的含义跨市场套用。
4. 本轮不设计或接入自动回退；Excel 失败或字段缺失时如实返回实际错误或缺口。旧通道代码保留，暂不纳入新的 Excel 工作流。此前 Excel 失败后切回原有渠道的安排由本次决定覆盖。
5. Excel 专用工作簿的路径隔离、独立实例、复用、前后清空、隐藏及单独关闭继续复用现有独立运行层。脚本不依赖 Computer Use；普通公式的二维批量组织见§1.1，不使用日期序列接口。
6. 旧来源及旧复权口径可能与新数据不一致，需要在切换方案中处理受影响行情缓存；本轮尚未列出清理目录、备份和执行清理。长期复用缓存、后续必要时强刷对应区间的需求保留，不能声称目前行情接口已有强刷参数。
7. 当前先处理 `.SH/.SZ/.BJ` 内地代码入口；`.HK` 尚未系统验证，港美股接入后置。公司合计字段可涉及 AH 公司的 H 股部分，不因此把纯港股入口纳入本轮优化。

### 1.1 Excel 二维整批取数（2026-11-05 已确认，待实现）

每次取数先为待补区间生成完整的“日期 × 上游字段”公式矩阵：一行一个日期，一列一个字段，公司/证券两层字段均包含在同一矩阵中。一次性填充整个区域的所有公式，等待结果完成后整块读取；不按字段逐列或按日期逐行调用 COM，也不逐单元格写入读取。取数前后清空工作页，读取后的结果仍按字段写入现有缓存。

成交量按脑图的“证券成交额 ÷ 不复权均价”在读取后计算；换手率直接读取上游结果，不依赖流通股本或流通市值。一次性填充描述的是 Excel 区域写入方式，不将其宣称为只有一次上游数据请求。现有独立运行层的一列公式接口仍需按该矩阵方式调整，尚未实现或完成整包验收。

## 三、需要验证的技术事项

这些是实现前的核实工作，不要求用户替程序选择参数或批量大小。

1. 逐字段取得可靠 Excel 公式并做最小真实调用，记录实际返回、单位、缺失、零值及复权选项；参数不得猜测。默认后复权的开高低收是否均能直取，以实测为准，不能沿用旧比例加工后冒充上游原值。
2. 验证日历日公式在周末、节假日、停牌及上市前的返回。对外行情日期需要保持交易日语义；上市前合法零值不能用作插件未就绪的判断。
3. 按§1.1的完整二维矩阵验证整包长区间性能，记录日期数、字段数、公式单元格数和耗时。此前 9,804 个日期的单字段测试不能等同于多字段压力测试通过；遇到实际容量或插件障碍时先报告，不擅自改为逐列、逐行或分块取数。
4. 验证 Excel 错误和字段缺失的实际返回。真实缺失与有效零值需按字段区分，不能把任意空值或零值都视为整包失败；通道处理遵循§1。
5. 明确缓存切换实现：识别旧月频填充数据及旧后复权，避免跨口径静默拼接；核实来源切换时对旧覆盖范围的影响。清理范围仅针对受影响行情缓存，公告、PDF、财报及公司信息不随之清空。具体目录、备份及操作清单需在执行前给出。
6. 保留现有调用入口、变量选择及周/月线加工的方案优先；前复权当前为本地加工，不在本轮悄悄新增另一套默认取数与缓存规则。依赖新后复权的加工与绘图须一起核对。

### 5.1 通道、证券类别与公司上市结构

| 判断层 | 依据 | 用途 |
| --- | --- | --- |
| 取数通道 | 输入代码的后缀 | `.SH/.SZ/.BJ` 走内地；`.HK` 走港股。价格币种不改变通道 |
| 当前证券类别 | 明确匹配证券代码及交易所的上游证券资料 | 识别 A、B 股，选择对应的证券总股本、币种及分项指标 |
| 公司上市结构 | 有来源和生效日期的上市证券关系及披露 | 解释纯 A、A+H、A+B、纯 B，说明总量和历史变化，不触发整套通道路由切换 |

当前 `routing.py` 已让 `.SH/.SZ` 的 A/B 股共用内部 `market="A"`，`.BJ` 保持独立内部标识；业务文案统一称内地通道即可，不要求先为改名重构枚举。

本轮证券资料只准备交易所、股份类型和上市日期，取数与缓存安排见[实施方案](内地Excel行情接入实施方案-2026-11-05.md)。股份类型使用用户已提供且实测的 iFinD 原式，不要求 AI 选择 A/B，不新增东方财富来源依赖。股份类型只证明当前证券类别，不证明公司没有其他上市证券；公司总量使用已确认厂商原值，不需要先构建跨市场关联档案。

输入代码同时定位研究公司和当前证券。价格、均价、量额及换手率按当前证券取数，公司总股本和总市值使用已核实的公司范围原式。后缀决定输入证券的内地通道；公司原式可以包含其他上市部分，不因此另开跨市场分项补取或加总流程。

### 5.2 拟统一的字段含义

| 字段 | 拟定含义及取法 | 状态 |
| --- | --- | --- |
| 高开低收、后复权价格 | 输入代码对应证券的行情，沿用该市场已确认原式 | 证券范围已确认；后复权开高低已完成小批直取，证据见支持情况§13.8 |
| 证券均价、后复权均价 | 输入代码对应证券的上游均价原值 | 原式及 B 股币种按 XMind 与支持情况核对 |
| 证券成交量、证券成交额 | 输入代码对应证券的标准交易量额，不含大宗及盘后，成交额单列币种 | 用户已确认；公司合计后置，不增加工具字段 |
| 证券换手率 | 输入代码对应证券的上游直取值 | 不再按成交量和流通股本计算；数值单位按真实返回核对 |
| 公司总股本 | 公司全股本，同一公司多个证券代码返回相同值时不可相加 | 用户已明确要求公司/证券两组；公司股本可含非上市股份 |
| 证券总股本 | 输入代码对应股份类别的总股本，包含该类限售股份 | 用户已确认；不能直接套公司全股本 |
| 公司总市值 | 公司层面的市值指标；内地采用厂商原值 | 内地映射与异常提示已确认，唯一规则见§5.6；不再等待非上市股份的补估值方案 |
| 证券总市值 | 与公司总市值分开暴露；内地采用厂商面向证券字段原值 | 内地映射已确认，唯一规则见§5.6；上游纯 B 股范围差异保留，不承诺自动矫正为股份类别市值 |

公司与证券字段由程序内部选择对应原式；AI 只提供证券代码及所需字段，不要求 AI 判断 A/B/H、上市结构或选择条件分支。纯 B 样本的非上市股份处理差异已作为上游事实记录，内地总市值最终选择见§5.6，不再采用此前“先确定非上市股份估值再映射”的待定方案。公司总股本仍包含全部已发行股份，不能因采用厂商市值原值而改写股本范围。

公司及证券总市值采用§5.6的固定上游原值；B 股各字段的币种分别保留并说明，不从报价币种推定均价、成交额或市值币种。

### 5.3 输入示例与执行边界

- 输入 `300308.SZ`：内地入口、当前证券为 A 股；价格量额对应该 A 股。公司/证券字段按§5.4整组提取，证券字段对应该 A 股类别。研究 H 股分项时使用已核实关联 H 股代码。图题或列名明确标注公司/证券及币种。当前公司 A+H 身份不得覆盖新增 H 股上市之前的历史。
- 输入 `000725.SZ` 或 `200725.SZ`：都走内地入口；分别返回 A、B 股行情，同时支持公司 A+B 合计及各自分项。公司总量可以相同，证券行情分开缓存，不能相加重复统计公司总量。
- 输入 `900948.SH`：内地通道、当前证券为沪 B；价格按该证券报价币种说明，不因美元报价转美股通道，也不因曾有 H 股改走港股。明确公司全股本与 B 股上市部分的差别；上游市值原值按实际范围附注。

以上示例是通用规则的说明，不是代码中的公司白名单。取数模块不按公司名称或具体代码专门适配；各字段依自身定义取数，不按公司类型另写重复算法。公司总股本可以包含非上市股份。

### 5.4 本轮使用场景讨论记录

公司总股本、证券总股本、公司总市值、证券总市值共四个字段，在同一次整组取数中一并提取并缓存。公司和证券两层地位相同，不设默认层级；公司总市值与证券总市值同等对待，不将证券字段作为额外请求才获取的补充。公司/证券这组语义覆盖纯 A、纯 B、A+B、A+H，无需让用户每次选择公司上市类型。成交量、成交额最终只做证券标准口径，公司合计留后续考虑。具体代码变量名与旧字段迁移尚未定稿，不在讨论中擅改接口。

此前提出的“单一上市时公司/证券总市值相等”和“自行定义上市股份合计”不再作为内地取数保证；用户在逐项比较五种市值后明确选择厂商原字段，并接受只提示异常、保留返回值的安排，见§5.6。

比较流动性使用各证券成交额、成交量及上游换手率。溢价比较需要各自不复权价格、相同估值日期与明确换汇口径，不能拿公司合计指标代替。

共用已有 Excel 执行器，分别维护内地和港股原式映射，按代码、日期、指标批写批读。继续按证券代码使用现有字段缓存，不新增公司级共享缓存体系。后复权开高低直取已补测，非交易日和长区间整包仍需后续验证；本轮没有改接口、路由、缓存或加工实现。

### 5.6 内地公司/证券总市值映射与提示（2026-11-05 已确认，待接入）

适用于输入后缀 `.SH/.SZ/.BJ`，包含内地 A 股、B 股及北交所证券；不按纯 A、AH、AB、纯 B 公司再分支选择其他总市值算法。

| 对外字段 | 固定 Excel 指标 |
| --- | --- |
| 公司总市值 | `ths_market_value_stock` |
| 证券总市值 | `ths_mv_sec_oriented_stock` |

用户所称 `mv_sec_oriented` 对应已实测的完整指标名如上。两者均保留上游返回原值，不自行补计非上市股份，不换用“总股本计算”“可回测”或 A/B 分项来矫正，不因出现倒挂而交换两值。

底层在同一证券、同一日期及同一币种的两个有效值可比较时，检测 `公司总市值 < 证券总市值`。满足条件时向调用方提示这一现象并保留原始数据；不报错、不将取数判为失败。该检查只提示倒挂，不能保证检出所有上游覆盖或定价问题；不另加用户未要求的检测规则。

`.HK` 输入的字段映射和检测尚未系统验证，不沿用上述内地字段；已有 AH 公司 H 端的少量探针记录只作为上游证据，不等于港股入口验收。`.BJ` 已纳入用户确认的规则范围，后续接入仍需完成该市场的 Excel 字段实测，不把已确认范围写成已测试通过。
