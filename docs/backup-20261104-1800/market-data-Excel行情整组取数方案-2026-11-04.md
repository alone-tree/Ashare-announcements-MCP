# Excel 行情整组取数讨论方案

日期：2026-11-04。状态：用户已确定本节列出的方向；字段公式、整包真实取数及具体改造仍待验证与确认，尚未进入实现。本文接替[常驻运行层原方案](market-data-Excel常驻取数方案-2026-11-04.md)中后续业务接入部分；该原方案已完成的独立运行层及其实测记录继续有效。

现行行为仍见[架构设计](market-data架构设计.md)。运行层使用方法见[运行说明](Excel常驻运行层.md)，基础测试证据见[实测报告](Excel取数基础实测-2026-11-04.md)。本文只维护本次拟变更，不把讨论结果写成已经生效的业务行为。

## 一、已确认方向

1. 行情优先从 iFinD Excel 获取。请求缺失日期区间时整组获取行情字段，再按现有流程保存本地缓存、读取缓存并进行加工；输出仍按调用方请求的变量选择，避免日后每增加一个变量就重新请求。
2. 范围扩展到高开低收、成交量、成交额、总股本、流通股本、总市值及流通市值，不再仅限原方案的总股本和总市值。PE TTM、PB、股息率作为后续扩展，不据此提前改财报和公司信息模块。
3. 复权统一选择 iFinD 默认后复权。用户此前选择的“现金分红口径”由本次决定覆盖；不额外指定现金分红或分红再投，也不把同一参数编号的含义跨市场套用。
4. Excel 取数失败时回到原来已有的渠道。用户本轮原话为：“失败了，切换回东方财富或者是新浪的原来的、已有的渠道。”沿用此前已确认的提示要求，说明实际来源、频率及缺失；不为这次回退另建一个尚不存在的免费源。
5. Excel 专用工作簿的路径隔离、独立实例、复用、前后清空、隐藏及单独关闭继续复用现有独立运行层。脚本不依赖 Computer Use；普通公式按日历日批量写入，不使用日期序列接口。
6. 旧来源及旧复权口径可能与新数据不一致，需要在切换方案中处理受影响行情缓存；本轮尚未列出清理目录、备份和执行清理。长期复用缓存、后续必要时强刷对应区间的需求保留，不能声称目前行情接口已有强刷参数。
7. 当前先处理 A 股行情；港美股复用执行框架的方向保留，公式、单位和交易日规则须分别核实，不承诺只替换字段名称就已完成适配。

## 二、现有渠道核对

以下为当前代码事实，便于落实“原来的、已有的渠道”，不代表新增回退已实现。

| A 股字段 | 当前取数或加工位置 | 作为备用时的边界 |
| --- | --- | --- |
| 高开低收、量额 | `providers/sina.py`，由 `service._field_chains` 路由 | 现有直接行情源是新浪；本轮未新增东方财富行情通道 |
| 后复权 | 新浪 `close_hfq`；工具层按价格比例加工开高低 | 不可直接声称与 iFinD 默认后复权口径相同；回退需明确提示 |
| 流通股本 | 新浪原始行情中的股本字段 | 沿用现有市场覆盖及单位规范 |
| 总股本、总市值 | `providers/ifind.py` 的 Python SDK | 现有早期区间仍可能是月末取样，必须提示实际频率；不能承诺免费源可补齐 |
| 流通市值、换手率 | `service.py` 本地计算 | 后续是否直接改为 Excel 对应字段，先核实真实公式和定义 |

`aggregator.commit_quote_batch` 已支持保存一次返回的多个字段，整组取数可以利用这一能力。当前来源切换会过滤旧来源记录、缓存覆盖命中也不会自动识别新复权口径，因此不能只替换一个取数函数就声称完成安全切换。

## 三、需要验证的技术事项

这些是实现前的核实工作，不要求用户替程序选择参数或批量大小。

1. 逐字段取得可靠 Excel 公式并做最小真实调用，记录实际返回、单位、缺失、零值及复权选项；参数不得猜测。默认后复权的开高低收是否均能直取，以实测为准，不能沿用旧比例加工后冒充上游原值。
2. 验证日历日公式在周末、节假日、停牌及上市前的返回。对外行情日期需要保持交易日语义；上市前合法零值不能用作插件未就绪的判断。
3. 验证整包长区间性能。此前 9,804 个日期的单字段测试不能等同于多字段压力测试通过。对外保持一次逻辑请求，内部是否需要分批由实际耗时与插件行为决定；批量填充不等于只有一次上游请求，也不证明账号无额度限制。
4. 验证 Excel 失败后的旧通道调用、频率和来源提示。真实缺失与有效零值需按字段区分，不能把任意空值或零值都视为整包失败。
5. 明确缓存切换实现：识别旧月频填充数据及旧后复权，避免跨口径静默拼接；核实来源切换时对旧覆盖范围的影响。清理范围仅针对受影响行情缓存，公告、PDF、财报及公司信息不随之清空。具体目录、备份及操作清单需在执行前给出。
6. 保留现有调用入口、变量选择及周/月线加工的方案优先；前复权当前为本地加工，不在本轮悄悄新增另一套默认取数与缓存规则。依赖新后复权的加工与绘图须一起核对。

## 四、拟改动位置与执行顺序

- 上游证据：先完成公式及小区间真实调用，再测整包长历史、隐藏复用和回退；新证据归入支持情况或既有实测报告，不复制本方案的决策。
- 取数模块：复用 `ifind_excel.py`，增加行情整包字段映射与返回适配，保留已确认的旧渠道备用。
- 调度与加工：调整 `service.py` 的来源路由、交易日组装及依赖新后复权的加工；利用现有整组缓存写入，必要的缓存识别与迁移不能遗漏。
- 接口及交付：接入 MCP/CLI 的专用 Excel 关闭入口、帮助与资源导出；获取接口是否需要变化，在具体方案中单列。未经要求不向实际用户版导出或推送。
- 文档：具体改造方案与代表性真实返回确认后再写业务代码；完成后按唯一归属更新架构、支持情况及决策记录。

本轮仅记录讨论并核对现有代码；未修改 provider、业务路由、MCP/CLI、导出脚本或缓存。

## 五、按后缀路由的内地行情打包提案（讨论中）

用户已确认公司/证券字段拆分及默认公司口径；逐字段取值、币种、历史聚合和兼容迁移仍待验证及确认，尚未实施。继续按代码后缀路由，并在统一中国市场通道处理 A、B 股以及多重上市公司的内地证券。原式、上市关系依据和样本实测只见[支持情况§12](../字段与数据源支持情况.md#12-excel-行情公式上市类型与股本市值口径实测2026-11-04)。

### 5.1 通道、证券类别与公司上市结构

| 判断层 | 依据 | 用途 |
| --- | --- | --- |
| 取数通道 | 输入代码的后缀 | `.SH/.SZ/.BJ` 走内地；`.HK` 走港股。价格币种不改变通道 |
| 当前证券类别 | 明确匹配证券代码及交易所的上游证券资料 | 识别 A、B 股，选择对应的流通股本、币种及分项指标 |
| 公司上市结构 | 有来源和生效日期的上市证券关系及披露 | 解释纯 A、A+H、A+B、纯 B，说明总量和历史变化，不触发整套通道路由切换 |

当前 `routing.py` 已让 `.SH/.SZ` 的 A/B 股共用内部 `market="A"`，`.BJ` 保持独立内部标识；业务文案统一称内地通道即可，不要求先为改名重构枚举。

证券身份可利用现有证券搜索返回的 `security_type_name` 等明确资料，采用代码和交易所精确匹配。该字段只证明当前证券类别，不证明公司没有其他上市证券。公司关联关系仍需单独取得证据；缺失时记未确认，不能默认纯 A，也不能靠公式返回 0 判定没有 B/H 股。身份资料拟按证券缓存复用，具体来源覆盖尚需在接入前验证。

输入代码同时定位研究公司和当前证券。价格及量额按当前证券取数，公司合计指标按字段所需范围取数；后缀决定每条证券的取数通道，不能用后缀限制公司合计指标的覆盖范围。iFinD 已提供且口径已核实的公司合计直接使用；公司合计缺少可靠直取公式时，提案允许内部根据已核实关系补齐其他上市证券分项。例如 A 股代码进入内地入口，公司流通合计若需要 H 股分项，内部仍按关联 H 股代码后缀使用港股公式；A 股行情本身保持内地通道。这属于合计指标的数据依赖，不是取数失败后的来源回退。

### 5.2 拟统一的字段含义

| 字段 | 拟定含义及取法 | 状态 |
| --- | --- | --- |
| 高开低收、后复权收盘、成交量 | 输入代码对应证券的行情，沿用该市场已确认原式 | 提案；原表样本已验证 |
| 成交额 | 输入证券的成交额，单独标注该公式的金额单位 | B 股样本存在人民币折算特征，正式单位仍待核实 |
| 总股本 | 公司全股本，同一公司多个证券代码返回相同值时不可相加 | 提案；不等同当前上市类别股本 |
| 公司总市值 | 公司层面的市值指标，默认请求 | 字段拆分及默认值已确认；为保证单一上市类别时与证券总市值相等，建议明确为各上市股份类别市值统一币种后合计，未上市股份不额外估值；这项范围定义仍需确认 |
| 证券总市值 | 输入代码对应股份类别的全部股份市值，包含该类限售股份，与流通市值区分 | 字段已确认；不是整个公司全股本乘当前证券价格，具体直取公式待补齐 |
| 公司流通股本 | 对应时点公司各上市股份类别流通股本合计 | 字段及默认公司口径已确认；原始分项定义及历史覆盖仍需核实 |
| 证券流通股本 | 输入代码对应股份类别的流通股本 | 字段已确认；A/B/H 分别选择该类分项，无需另设模式 |
| 公司流通市值 | 公司各上市股份类别流通市值统一币种后合计 | 字段及默认公司口径已确认；不能直接套用名称相近但范围不一致的原式 |
| 证券流通市值 | 输入代码对应股份类别的流通市值 | 字段已确认；尚缺的直取原式或计算方式仍需核实 |
| 原始合计及分项 | 按实际可得字段分别缓存，保留币种和覆盖范围 | 已核实部分可以使用；缺失分项不能视作 0 后声称合计完整 |

“公司总市值”和“证券总市值”的字段拆分已确定，但不能据此直接把 iFinD 名为“总市值”的所有返回都放进公司字段。纯 B 样本的非上市股份处理不一致；“只在一个市场上市”也不证明公司全股本均属于该上市证券。若采纳上述上市股份合计定义，单一上市类别的公司/证券市值可以相等，但公司全股本仍可能大于该类上市股本。不得用 B 股价乘公司全股本补造非上市股份估值；实际源字段必须逐项匹配最终定义。

公司合计与分项优先使用口径已经验证的上游原值。缺少直取公式时，可计算的提案包括各类不复权价格×同类流通股本，再按同一估值日期的汇率统一币种求和；具体计算、汇率源与休市日期对齐尚未批准实施，不能拿后复权价格计算当前市值。B 股可使用用户已提供的人民币市值原式，并继续核实其限制条件。公司总股本可含非上市股份，公司流通合计不把这些股份当成上市可交易股份。

### 5.3 输入示例与执行边界

- 输入 `300308.SZ`：内地入口、当前证券为 A 股；价格量额对应该 A 股。默认请求公司总市值、公司流通股本及公司流通市值；显式请求证券字段时，对应该 A 股类别。研究 H 股分项时使用已核实关联 H 股代码。图题或列名明确标注公司/证券及币种。当前公司 A+H 身份不得覆盖新增 H 股上市之前的历史。
- 输入 `000725.SZ` 或 `200725.SZ`：都走内地入口；分别返回 A、B 股行情，同时支持公司 A+B 合计及各自分项。公司总量可以相同，证券行情分开缓存，不能相加重复统计公司总量。
- 输入 `900948.SH`：内地通道、当前证券为沪 B；价格按该证券报价币种说明，不因美元报价转美股通道，也不因曾有 H 股改走港股。明确公司全股本与 B 股上市部分的差别；上游市值原值按实际范围附注。

以上示例是通用规则的说明，不是代码中的公司白名单。取数模块不按公司名称或具体代码专门适配；各类分项依自身定义取数，不按公司类型另写重复算法。纯 A 的公司流通合计可与 A 股分项一致，纯 B 的公司上市流通合计可与 B 股分项一致，但不能据此认为所有公司总股本均已上市。

### 5.4 本轮使用场景讨论记录

此前询问“默认流通口径选当前证券还是公司合计”，用户没有选择其中一项，而是明确提出两类并存需求：日常以公司整体研究并绘制总市值/流通市值；深入时分别研究 A/H 市场流动性及溢价。该问题不再作为二选一等待回答。

随后用户明确决定：总市值拆为公司总市值、证券总市值；流通股本及流通市值同样拆分；默认请求公司字段，需要时显式请求证券字段。公司/证券这组语义覆盖纯 A、纯 B、A+B、A+H，无需让用户每次选择公司上市类型。具体变量名与旧字段迁移尚未定稿，不在讨论中擅改接口。

用户同时提出单一上市时公司/证券总市值相等。针对纯 B 存在非上市股份的已验证边界，提出将公司总市值明确定义为各上市股份类别市值合计的建议，尚不视为用户已经明确选择了未上市股份的处理方式。

比较流动性使用各证券成交额、成交量及与同类股本对应的换手率；公司合计流通市值仅表达规模，不替代单市场流动性指标。溢价比较需要各自不复权价格、相同估值日期与明确换汇口径，不能拿公司合计指标代替。

共用已有 Excel 执行器，分别维护内地和港股原式映射，按代码、日期、指标批写批读。继续按证券代码使用现有字段缓存，不新增公司级共享缓存体系。原表只有后复权收盘原式，后复权开高低、非交易日和长区间整包仍需后续验证；本轮没有改接口、路由、缓存或加工实现。
