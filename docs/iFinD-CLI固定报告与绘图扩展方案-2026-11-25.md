# iFinD CLI固定报告与绘图扩展方案（2026-11-25）

状态：用户已确认方案，待实施。本轮只读调研，未改代码。
依据：三份事实底稿（固定报告脚本、绘图规范、CLI扩展点）与`iFinD-CLI实操改进讨论稿-2026-11-25.md`。

已确认决策（2026-11-25）：
- 财报默认报告期：甲案，自动探测最新已披露期。
- 绘图范围：四个模板全做。
- 缺失的四块（IPO/分红/营收结构/盈利预测）：先留空标注缺口，不硬造。

## 一、要解决的问题

用户要做上市公司研究时，旧流程是跑研究项目里的`上市公司标准数据提取.py`，产出一套固定文件（Markdown骨架、财务CSV、行情CSV、公告索引、行情图）。现在要改用iFinD CLI取数，但CLI只有单点场景取数，没有"一键产出研究报告骨架"的能力，也没有绘图。目标是让指南里只写"调CLI的某个命令"，不再两处维护取数脚本。

## 二、总体设计

三条能力，全部加在iFinD CLI包内，保持与market-data零import依赖：

1. 分板块CSV导出：复用现有`fetch_scene`的`export_path`，不新增取数命令。
2. 合并报告命令：新增`export_report`，把各板块CSV/JSON拼成固定Markdown骨架。取数仍由各板块命令负责，合并命令只做拼装。
3. 绘图命令：新增`draw`，包内独立`chart.py`实现，提供若干模板。

所有新命令沿用顶层`cmd`字段，函数签名`def xxx(req: dict) -> dict`，不碰分发主流程。

## 三、改动一：分板块CSV导出

事实：`fetch_scene`与`_fetch_table_scene`均已支持`export_path`；`to_csv`用utf-8-sig、自动建目录、返回路径/行数/列名。11个场景均可独立导出。显式传`export_path`时records全量返回，不截断。

做法：不改代码。每个板块调用一次`fetch_scene`，带`export_path`指向研究项目目录。每个代码单独CSV就按单`code`循环调用。

板块与场景对应（11个现有场景）：
- 公司基本信息→工商信息
- 股东→十大股东
- 行情→历史行情（配合估值快照补市值）
- 估值→估值快照
- 三表→资产负债表/利润表/现金流量表
- 单季表→利润表单季/现金流量表单季
- 指数→指数成分股/指数进出记录

旧脚本有而CLI无现成场景的板块：IPO信息、分红、营收结构（segments）、盈利预测。这四块需要后续决定是否补场景，本期先标注缺口，不硬造。

文档补充：`usage.md`、`help.py`、`README.md`、Skill说明里写清export_path用法。属于文档同步，不是代码改动。

## 四、改动二：合并报告命令export_report

关于"合并脚本放研究项目还是放CLI"：用户明确要求"指南里只说调用CLI的xx命令、不两处维护"，因此放在CLI包内，新增`export_report`。这是对用户诉求的响应，覆盖第三路调研"放研究项目脚本"的建议。

命令设计：
- 输入：各板块导出的CSV/JSON路径（或一个目录+命名约定）、公司名称与代码、输出Markdown路径。
- 行为：读取各板块数据，按固定章节顺序拼装Markdown；章节与旧脚本`build_report`对齐（公司基本信息、股东与控制权、资本运作、行情走势及分红、财报摘要、公司业务、盈利预测与估值、附录三表）。
- 只做拼装，不内置取数、不内置公司分析规则。没有数据的板块留空节并注明未取到，不推算、不补造。
- 遵守报告写作规范：不加Markdown加粗（复用旧脚本`md.replace("**","")`的做法）。

轻量性：复用旧脚本已有的渲染函数逻辑（`markdown_table`、`render_basic_info`、`render_shareholders`、`render_financial_summary`、`render_financial_appendix`等），作为新模块`report.py`纳入CLI包，不另起复杂框架。一次只拼装，不做增量、不做模板系统。

目录归属说明：报告章节与表格排版规则仍在研究项目的报告写作规范里定义，CLI的`report.py`只负责按该规范拼装，不复制业务规则。

## 五、改动三：绘图命令draw与模板

约束：chart_service.py依赖market_data_mcp.service，按零import铁律不能直接import。包内新建`src/ifind_excel_tool/chart.py`，只移植绘图无关取数的部分（Agg后端、中文字体、K线蜡烛、事件标注、对数轴、高低点、保存PNG）。matplotlib已装（3.11.1），labellines未装且按克制原则不引入。

数据流两步：`fetch_scene`导出行情CSV → `draw`读CSV出PNG。取数与绘图分离。

命令设计：`{"cmd":"draw","template":"kline_volume","data_path":"...csv","output":"...png", ...模板参数}`。

模板清单（按用户点名场景）：
- `kline_volume`：标准K线+成交量副图+MA5/10/20/60，红涨绿跌，主副图高度比3.2:1。
- `kline_log_volume`：同上，价格轴与量轴改对数；数据含0或负自动退回普通坐标。
- `close_mcap_events`：双轴折线（总市值+前复权收盘价）+事件标注，移植`绘制市值与前复权股价.py`的按字宽分层避让。
- `close_line_keypoints`：单折线+高/低/最新点标注+回撤阈值（默认30%）高低点。

模板变动为主，命令不变。每个模板只支持一两个必要参数，不做复杂配置系统。

公共绘图规范（chart.py内固定，不逐模板重复）：自动色板tableau-colorblind10、16×11 DPI200、背景#FAFAFA、网格alpha0.3、隐藏上右边框、中文字体探测、inline标签不用图例框、事件标注自动避让。

事件标注支持CSV（date,description两列）与JSON数组两种入口，事件日对齐到最近的交易日。
