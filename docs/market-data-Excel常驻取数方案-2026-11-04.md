# Excel 常驻取数接入方案

日期：2026-11-04。状态：独立运行层原型已实现；已初始化实例的隐藏批量取数通过，冷启动插件初始化未通过，尚未完成整体验收。MCP、CLI、SDK 分流和导出逻辑留待后续接入。实际使用入口见[运行说明](Excel常驻运行层.md)，证据见[实测报告](Excel取数基础实测-2026-11-04.md#常驻运行层实测2026-11-04)。

本文是本轮唯一实施计划。现行行为仍以[架构设计](market-data架构设计.md)为准；已有测试及失败边界见[实测报告](Excel取数基础实测-2026-11-04.md)。实施完成后将有效规则归入架构设计，上游客观证据归入支持情况，历史摘要归入决策记录。

## 一、已明确的安排

1. 仓库内保存一个专供工具使用的空白 Excel 文件，随程序导出到用户版。
2. 工作簿位置跟随实际运行的程序包，以完整绝对路径识别。开发版、各工作树和用户版分别使用自己目录中的文件。
3. 需要实际请求 iFinD 时，先复用已打开的专用工作簿；尚未打开才启动。
4. 每次请求先清空指定工作页，再批量写入普通 `thsiFinD` 公式，等待完成，批量读取，最后再次清空。按日历日生成独立公式，不用日期序列接口。
5. 请求结束后工作簿和 Excel 常驻，不自动关闭。另提供一个单独关闭入口，供 AI 完成整轮任务后调用。
6. 隐藏及关闭只作用于专用工作簿所属的独立 Excel 实例。先保持可见，稳定性确认后再启用隐藏。
7. Excel 优先，失败回到现有 Python SDK 分支；SDK 成功时沿用正常返回，并明确其实际频率与缺失。两者均失败沿用原错误处理。
8. 现有取数之后的缓存写入、缓存读取、覆盖判断、月频填充与后续加工均保持原状。已覆盖的缓存继续复用，不因接入 Excel 自动重取。区间强刷不在本轮增加。

## 二、文件与路径

新增资源：`src/market_data_mcp/data/ifind_workspace.xlsx`，仅含一个空白工作页“data”。新增生命周期模块：`src/market_data_mcp/ifind_excel.py`，放在包根目录。

路径由模块位置计算：

```python
Path(__file__).resolve().parent / "data" / "ifind_workspace.xlsx"
```

这里的 `__file__` 属于 `ifind_excel.py`。不使用当前工作目录、业务缓存根目录或固定开发目录寻找工作簿。

| 运行位置 | 专用文件 |
| --- | --- |
| 当前工作树 | 当前工作树的 `src/market_data_mcp/data/ifind_workspace.xlsx` |
| 用户版 | 用户版的 `market_data_mcp/data/ifind_workspace.xlsx` |

绑定已打开文件时必须核对完整路径；同名文件不能作为匹配依据。不能直接把 `GetActiveObject("Excel.Application")` 返回的第一个实例当成目标。开发版关闭入口也必须只定位开发版路径。

工作页仅作临时计算区。取数期间不保存临时公式或结果，磁盘文件保持空白模板；结果仍交给原缓存层保存。正常结束及可执行清理的异常路径均清空工作页，关闭时不保存修改。下次请求开头仍无条件清空，以清除上次中断的残留。

## 三、启动、复用及清空

顺序为：按完整路径定位已运行工作簿 → 如未打开则正常启动独立 Excel → 确认目标工作簿及插件可用 → 清空“data”页 → 批写公式 → 等待全区域完成 → 批读结果 → 清空“data”页 → 保持常驻。

首次独立启动拟使用 Excel 官方 `/x` 参数；它表示新建独立进程。命令结构为：

```text
EXCEL.EXE /x "专用工作簿的绝对路径"
```

本机 Excel 路径应从安装信息定位。已有实测表明直接 COM 创建 Excel 会阻塞，本轮不把该方式作为已验证的启动路线。正常启动后如何可靠绑定目标进程和工作簿，必须先完成最小实测，再固化到模块。

同一完整路径对应的请求串行执行，清空、写入、等待、读出、再次清空均位于同一临界区；关闭入口也遵守该互斥。MCP 与 CLI 同时访问同一路径时不能相互清空。不同目录的工作簿分别管理。

工作页用 `sheet.Cells.ClearContents()` 清除全部公式与值，不触碰其他工作页。写入与读取采用整块 `Range.Formula2` / `Range.Value2`，不逐单元格 COM 调用；不调用 `CalculateFull()`。完成条件复用已验证探针：全区域加载文字消失，检查错误及结果类型，不能仅依赖 `CalculationState == 0`。

登录依赖用户已设置的 iFinD 插件自动登录，不增加鼠标、键盘模拟或 Computer Use。自动登录未完成、插件不可用或 Excel 失败时走 SDK 分支。

同步 COM 调用本身可能阻塞；回退机制的超时必须覆盖此边界，不能只给结果轮询计时。具体隔离方式在最小测试中确定，不通过强制关闭其他 Excel 恢复。

## 四、隐藏与关闭入口

`Application.Visible = False` 作用于整个 Excel 实例，因此先验收独立启动及实例归属，再启用隐藏。首次正常启动可能短暂出现窗口；“启动后隐藏”和“从启动起完全无窗口”分别记录，不承诺尚未验证的效果。

新增无参数入口：

```text
MCP: close_ifind_excel()
CLI: {"tool": "close_ifind_excel"}
```

关闭时仅查找当前运行包的专用工作簿；未打开则直接返回，不为了关闭而启动。存在时先清空“data”页，再 `Close(SaveChanges=False)`。确认实例中没有其他用户工作簿后才 `Quit()`；如果存在其他用户工作簿，保留其 Excel 实例，不保存或丢弃其内容。返回关闭结果或实际错误，不增加任意文件路径参数。

不另增打开、清空、查询状态等 MCP 工具。默认取数自动管理打开和复用，关闭入口单独提供。

## 五、取数接入范围

在各指标原有五年切段与月末采样之前尝试 Excel，成功后返回该指标既有的 provider 数据结构；失败才执行原 SDK 逻辑。Excel 成功时不能先要求 SDK 登录，也不能把 Excel 已获取的完整日历日序列再送进旧 SDK 采样分支。

本轮最先接入已完成真实调用的 A 股总市值公式：

```excel
=@thsiFinD("ths_mv_back_test_stock","300502.SZ","2026-11-04")
```

用代码与日期替换该已验证模板中的对应值，不猜测其他指标或市场的参数。其余 iFinD 指标按现有已确认 Excel 公式逐项实测后接入；尚无已验证公式的指标保留 SDK。不能声称本次总市值测试已覆盖股本、美股行情、汇率、公司信息和营收结构。

Excel 与 SDK 均属于 iFinD 通道，不改变各字段原定数据源。零值、非交易日、空值保持上游实际返回，沿用该字段现有规范化处理，不在新生命周期模块补月频或加工数值。

### 本轮执行边界（用户确认后补记）

本轮只新增独立运行模块、空白资源及其测试与运行说明。上表中的 provider 分流、MCP/CLI、帮助登记、依赖导出及导出脚本修改均暂不执行，也不测试 SDK 回退。先提供普通 Python 函数供逐步真实调用，功能包括打开、读取状态、切换可见性、批量公式取数、复用、清空和关闭；这些函数不自动注册为工具。

工作页名称遵循用户对本稿的修改，统一使用 `data`。不覆盖或还原该人工修改。绑定可以采用 Windows 原生对象模型接口定位 Excel 窗口所属实例，不模拟输入、不移动焦点；避免依赖第一个活动实例以及 Office 失去焦点后才注册的运行对象表。

实测遇到 PERSONAL 文件锁后，增加仅对本次新进程该文件锁提示的 Windows UI Automation Invoke；不依赖 Computer Use 工具，不模拟鼠标键盘，不处理认证窗口。实现与适用边界在运行说明维护，失败过程及实际结果在实测报告维护。

## 七、逐步验收

每项真实调用单独执行，报告实际结果后再继续，不用大循环批量扫测。

1. 独立启动与精确绑定：正常打开专用文件，确认工作簿完整路径、Excel 进程、工作页与插件；无 Computer Use。
2. 单点及小批：复用已验证公式，检查清空 → 写入 → 等待 → 读出 → 再清空；只留下空白常驻工作簿。
3. 连续两次请求：第二次复用同一实例和文件，确认前次公式无残留，分别记录启动与热态耗时。
4. 与普通 Excel 共存：保留独立测试工作簿及样本值，检查隐藏和关闭专用实例后，普通工作簿内容与可见状态不变。
5. 隐藏后取数：先正常启动再隐藏，验证新请求仍能计算、读取和清空。未经本项通过，保持默认可见。
6. 大区间：沿用贵州茅台 `2000-01-01` 至 `2026-11-03` 的已验证样本，确认常驻版单批返回 9,804 个日历日位置并在结束后清空，记录性能及数据差异。
7. 路径隔离：在专门测试目录生成导出副本，从不同 cwd 运行；开发与副本分别打开各自文件，关闭其中一个不影响另一个。正式用户版不参与测试。
8. 回退及接口：验证 Excel 失败时原 SDK 分支仍可工作，MCP/CLI 可发现并调用关闭入口，未知参数仍显式拒绝；验证缓存命中时不会打开 Excel，现有缓存与加工测试通过。

已完成的基础实测仍以[实测报告](Excel取数基础实测-2026-11-04.md)为证据；以上项目的实际进度以后续实测报告为准，本稿保留为尚未全部完成的接入计划。

### 2026-11-04 插件禁用状态复核后的实施补充

用户指出插件掉落后，只读核对确认 Excel 的 `Resiliency/DisabledItems` 中确有 iFinD DLL 与 ProgID。备份后仅恢复这一条禁用记录，正常关闭并冷启动复测，原失败样本恢复正确返回。此次正常冷启动失败已有实际原因证据，不能继续泛称插件正常启用时的冷启动不稳定；历史失败记录仍保留。

在已确认的独立运行层范围内补充禁用状态检查：取数前读取本用户的 Excel 禁用项目，发现 iFinD 项则明确报告插件被禁用，不把函数加载项的零值作为正常结果。运行模块只检测，不自动删除禁用记录，不覆盖用户主动禁用的选择，不清理其他加载项。

随后验证恢复插件后的隐藏冷启动及与普通测试工作簿共存；仍不接入 MCP/CLI、SDK 分流或业务缓存。

- [Excel 命令行开关 `/x`](https://support.microsoft.com/zh-cn/office/lifecycle/command-line-switches-for-microsoft-office-products)：独立进程启动。
- [Application.Visible](https://learn.microsoft.com/en-us/office/vba/api/excel.application.visible)：Excel 应用实例可见性。
