## 一、这份方案要解决什么

现在 AI 要用这个 CLI 拿数据，得先知道「去哪查」：有的指标在公式库、有的在固定场景、派生计算又藏在报告排版里。同一个业务问题（比如「拿毛利率」）可能要在三四个地方翻，还要自己判断走哪条命令、自己把原始金额相除。

目标是让 AI 只面对一件事：业务上要什么数据，就搜什么指标。搜到之后按提示发命令，拿回加工好的结果。底层到底是一条 Excel 公式、一段自定义计算、还是一个报表函数，AI 不需要知道，也不应该知道。

一句话：把一个工具能拿到的全部业务数据，收进同一个搜索范围，让 AI 搜索、选择、调用、拿结果，中间不再自己加工。

## 二、我要的效果：AI 的完整工作流

```mermaid
flowchart LR
    A["1 搜索指标<br>按业务需要搜全部能力"] --> B["2 拿到用法<br>指标定义 + 命令 + 参数 + 返回样式"]
    B --> C["3 输出参数命令<br>按提示填参调用 CLI"]
    C --> D["4 底层取数<br>Excel 公式 / 报表函数自动执行"]
    D --> E["5 基础加工<br>自动取齐依赖并计算<br>单位 / 货币 / 小数位"]
    E --> F["6 返回结果<br>加工完成的数据"]
```

六步各自的要求：

| 步骤 | AI 做什么 | CLI 必须给到什么 |
|---|---|---|
| 1 搜索 | 按业务需要输入关键词，范围是整个工具的全部能力，不是一个子集 | 返回所有命中的业务数据能力，不阉割 |
| 2 拿用法 | 读搜索结果，判断哪个指标是自己要的 | 每个指标告诉 AI：这是什么数据、用哪条命令、传什么参数、返回大概长什么样 |
| 3 调命令 | 按用法填参数发命令 | 命令形式统一，AI 不用先判断底层是公式还是场景还是派生 |
| 4 取数 | 不参与 | 底层按指标自己把需要的 iFinD 原始数据拿到；原始公式型无需额外计算 |
| 5 加工 | 不参与 | 派生指标自动取齐依赖、完成计算；通用参数（单位、货币、小数位）在这里统一处理 |
| 6 拿结果 | 直接用结果继续研究 | 返回的是加工完成的数据，AI 不再重复处理 |

关键约束：第 1 步的搜索范围必须是全部支持的能力，行情、财务、报表、指数成分、指数进出、以及以后零散新增的自定义指标，全都在同一个地方能搜到。不允许分成「公式库搜得到、场景搜不到」这种割裂。

## 三、统一搜索要覆盖什么

搜索的本意是告诉 AI「你可以拿到哪些数据」，不是告诉它「库里存了哪些公式」。所以搜索范围按业务数据算，不按存储形式算。

当前工具实际支持的能力，全部纳入：

| 能力族 | 当前形态 | 纳入搜索 |
|---|---|---|
| iFinD 单格公式指标 | 已验证公式库 807 条（行情、三表、股本、估值、基本资料等） | 是 |
| 多候选取值指标 | 场景里的固定资产、在建工程这类「取较大值」规则 | 是，作为指标的一种，不再藏在场景内部 |
| 固定场景取数 | 工商信息、十大股东、利润表、分红、盈利预测、营收结构等 | 是 |
| 报表函数型取数 | 指数成分股、指数进出记录（底层是 THS_RPT / THS_DR，不在 807 条公式库里） | 是，和公式型同等对待，不能漏 |
| 自定义派生指标 | 目前散在报告排版里的毛利率等，以后统一进自定义库 | 是，且优先 |
| 指标组 | 用户自定义的常用科目组合（如「利润表常用科目」），定义后自动进搜索库 | 是，无需单独入库 |
| 特殊能力 | 探最新报告期这类非取数的查询能力 | 是，作为一种指标行为暴露 |

这里特别确认一点：指数成分股、指数进出记录在公式库里搜不到，因为它们是报表函数型场景，不是 `thsiFinD` 单格公式。但它们就是业务数据，必须进统一搜索范围。搜索结果里要能像其他指标一样看到「这是什么、怎么调、返回什么」，不能因为底层形态不同而缺席。

## 四、指标库只有两种类型

录入指标只有两条路，不再有第三种：

| 类型 | 录什么 | 底层来源 |
|---|---|---|
| iFinD 原始型 | 直接录入底层 Excel 能力，含单格公式与报表函数两种来源 | 公式库 807 条 + 报表函数型场景配置 |
| 自定义型 | 在自定义库里写「依赖哪些指标 + 怎么算」，对原始指标加工 | 不直接取数，底层自动调依赖指标 |

自定义库优先：当自定义指标与 iFinD 原始指标同名时，搜索和调用都以自定义 definition 为准。这样可以定义一个和原始 Excel 同名的指标，让 AI 拿到的是我加工过的版本，而不是原始值。

底层行为：AI 要获取自定义指标时，CLI 自动把该指标依赖的所有 iFinD 原始数据取回来，完成计算后再返回。如果某条定义就是一条原始公式，则无需任何计算，直接返回原值。AI 全程不接触 Excel 公式，也不做二次加工。

基础加工统一放在取数层，不只服务于某一个指标：

- 多个指标的依赖计算（派生指标之间可以互相依赖）
- 数字单位换算与货币换算
- 保留小数位
- 分母为零、依赖缺失时的处理规则

这些能力以通用参数的形式暴露给指标定义，而不是每个指标各写一套。

## 四之二、指标组（组合指标）

搜索除了单个指标（如「营业总收入」），必须同时支持「一次拿一组指标」。指标组就是用户自定义的常用科目组合，例如「利润表常用科目」= 营业总收入、营业成本、毛利率、营业利润、归母净利润等。

关键规则：

| 规则 | 说明 |
|---|---|
| 定义即入库 | 指标组一旦定义，就自动进入统一搜索库，不需要走单独的入库流程 |
| 和单指标同范围搜索 | AI 搜「利润表科目」时，能同时搜到相关单指标和相关指标组，由 AI 按需要选一个或一组 |
| 组内能放任意指标 | 既可放 iFinD 原始指标，也可放自定义派生指标（如毛利率），还可放另一个指标组，支持嵌套 |
| 一次命令取回 | 用一条命令拿回整组数据，底层自动合并取数、完成组内派生计算 |
| 不额外入库 | 定义指标组这件事本身就是入库，不要求先把组内每个成员单独录一遍 |

现在场景层的固定场景（工商信息、利润表等）就是这个想法的一部分实现，但组织比较混乱：有的场景是一次取一张表，有的是多候选取值，有的是报表函数。统一后，指标组作为一种普通的指标定义存在，和单指标共用同一套搜索与调用方式，场景层的混乱由这层统一收口。

## 五、搜索结果长什么样

搜索返回的是「用法说明」，让 AI 看完就知道下一步发什么命令。每条至少包含：

| 字段 | 作用 |
|---|---|
| 指标名与说明 | 判断是不是自己要的业务数据 |
| 指标类型 | 原始型或自定义型；AI 不需据此做不同操作，仅用于展示口径来源 |
| 调用命令 | 明确用哪条命令拿它 |
| 参数说明 | 要传哪些参数、各自含义、示例值 |
| 返回样例 | 返回结构大概什么样、单位是什么、精度是多少 |

AI 的体验应当是：搜「毛利率」，看到一条带用法说明的指标，发一条命令，拿到算好的百分比。搜「沪深300成分股」，同样看到一条带用法说明的指标，发一条命令，拿到成分名单。两者在 AI 眼里是同一种东西。

## 六、当前距离与目标形态

目标形态是六步全部贯通、两种类型统一。现状是部分环节已有、部分缺失：

| 环节 | 现状 | 差距 |
|---|---|---|
| 搜索 | 公式库可搜 807 条公式 | 搜不到自定义指标、多候选指标、报表函数型能力；范围不统一 |
| 用法 | 返回公式模板、参数、单位、读数通道 | 不告诉 AI 用哪条命令、返回样例是什么 |
| 命令 | 公式走 run/text，场景走 fetch_scene，报表函数走表格场景 | 多条路径并存，AI 要先判断走哪条 |
| 取数 | Excel 执行层成熟，实测充分 | 无缺口，保留即可 |
| 加工 | 派生计算硬编码在报告排版层；多候选取值藏在场景层；单位换算在排版层 | 没有自定义库，也没有统一的基础加工层 |
| 返回 | 裸数值、记录、Markdown 三种形态并存 | 格式不统一，AI 拿到后仍需处理 |

结论：不是重做。Excel 执行层和 807 条公式原样保留；要做的是补一个自定义指标库，并把搜索、命令分派、基础加工三处接线，让所有能力进同一个搜索范围。

## 七、实施边界

本方案只定义目标效果和框架，不包含具体的数据结构、命令名、代码落点。这些实现细节由 AI 按现有项目约定决定。

已明确的实现约束：

- 自定义库优先，同名时覆盖原始定义
- 派生指标可嵌套依赖，多个指标共享同一依赖时合并取数，不重复跑 Excel
- 通用参数（单位、货币、小数位）在取数层统一处理，不放进报告排版
- 不阉割搜索范围：公式型、报表函数型、场景型、自定义型全部可搜
- 保留 run / text 作为逃生舱：只有统一库里没有的能力，才让 AI 直接写 Excel 公式
