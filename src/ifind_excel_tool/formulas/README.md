# 第一块 公式录入

这块只放 iFinD 公式本身：录了什么公式、怎么把模板填成可执行公式。不判断业务含义。

两类公式，分开存：

| 文件 | 形态 | 例子 |
|---|---|---|
| `single.jsonl` | 一条公式取一个值 | 某天某股前复权收盘价 |
| `batch.jsonl` | 一条公式让 Excel 函数把整张表写到下方 | 指数成分股、指数进出记录 |

`notes.jsonl` 存按公式路径生效的通用说明。`legacy/catalog.jsonl` 是禁用文件，见下文。

## 单点公式字段

| 字段 | 含义 |
|---|---|
| path | 插件函数搜索树路径，斜杠分隔，只到分组层（如资产负债表/流动资产），不含具体科目名。累计与单季度是并列路径，不可混用 |
| name / aliases | 中文名与别名。name 前导空格是报表内层级缩进，勿 strip；层级同时以 parent_name 标直接上级 |
| indicator | iFinD 指标码 |
| formula_template | 带 `{code}`/`{date}`/`{type}` 占位符的完整公式 |
| definition / algorithm | 只记影响取数、计算或解释的定义与算法。名称已能说明或原文只有套话时留空 |
| parameters | 数组，每项 position/name/meaning/options/default |
| source / unit | 来源与单位，原文为空则留空 |
| example / example_value | 示例公式与实测值 |
| verification | verified 或 verified_with_caveat |
| verified_at / evidence | 验证日期与证据出处 |
| notes | 优先记录从名称看不出的口径、算法差异与使用限制。复算过程放 evidence |
| reading_mode | matrix（数值）或 text（文本，执行时走文本通道） |

`verified_with_caveat` 表示公式正确但有限制条件，返回数据时必须带出 notes 提示。

## 科目别名（2026-11-26 定）

`aliases` 是用户给科目起的常用称呼，通常比 iFinD 原名短，如「扣非净利润」。

- 检索时别名与原名同等参与匹配。
- 展示时中文别名优先，没有别名才用原名。
- 英文别名（如 `gross_margin`）只参与匹配，不作为展示名——给人看的应该是中文。

## 批量公式字段

一条公式让报表函数把整张表写到公式下方，与「一个指标一个值」完全不同，所以单独存。

| 字段 | 含义 |
|---|---|
| name | 科目名，检索时用 |
| kind | 固定为 `batch` |
| function | `THS_RPT` 或 `THS_DR` |
| report | 报表编码，如 `idx_weight`、`p03316` |
| inputs | 输入参数名列表 |
| input_labels | 输入参数的中文说明 |
| code_input | 哪个输入参数接收 `code`，让调用方可以用统一的 code 传代码 |
| defaults | 输入参数默认值 |
| fields | 输出字段代码 |
| field_labels | 输出字段中文名 |
| field_units | 输出字段单位 |
| tail | 固定尾部参数 |
| notes | 使用说明 |

实测（2026-11-24）：`rows`/`cols` 的数值不影响返回行数，函数按实际数据量输出；那个空参数不能省。公式全内联，不引用单元格。

## 通用说明

只有同一条规则确实适用于多个科目，才写成通用说明。用最窄的有效路径约束范围，并确认相邻科目不会误命中。单项算法、例外和反例放到对应科目。

| 字段 | 含义 |
|---|---|
| id | 序号，简单递增 |
| scope | 生效范围，按公式 path 前缀匹配 |
| note | 规则正文 |

前缀匹配是有意设计：scope 写累计报表路径时，其说明会同时命中单季度报表。需要只覆盖某一分支时，把 scope 写到该分支的完整路径层级。

## 港股、美股财报口径

港股、美股财报数据的 iFinD 字段与公司公告字段不完全相同，存在不稳定的勾稽关系，必要时直接对照公告查看原值。

## 数据来源等级（2026-11-18 踩坑后定）

用户从 iFinD 插件界面手动复制的公式原文属于正式库来源，实测用于确认实际调用、参数和数据口径。真实 Excel 取数且人工确认的结果也可作证据。

`tools/candidate-formulas.jsonl` 用于登记待核对公式。批量收到的插件公式是筛选素材，正式库只录入有明确用途的指标。入选指标若多次返回 0 或口径仍待确认，记录已知写法、实测情况和限制。

不可靠来源：`legacy/catalog.jsonl`（来自 excel_description.dat，信息可能旧/错/笼统）、2018 手册、历史仓库、AI 自己填的 path/name/source/unit。严禁查询、核对或覆盖已验证库。

具体教训：

- 不得拿 catalog 的 source/unit 覆盖已有记录。曾把用户实测的港元数据「港元」改成 catalog 的「元」。
- 枚举只认用户贴的参数说明或实测确认的，不从相似指标搬。曾把复权枚举误塞给只有 100/107/108 的指标。
- path/name 以用户从插件界面贴的为准，不自己按理解填，不从历史仓库路径映射推测。
- 无 example_value 的记录不得标 verified，只能 verified_with_caveat。
- 修正经 `tools/update_verified.py` 并记录到 `tools/correction-log.jsonl`；只改用户确认过的字段。

总原则：宁可库里少几条，不能有一条错的。

## 录入与验证流程

1. 通读原文后先筛选。优先录入研究中常用、覆盖已知缺口，或提供独立数据口径的字段。对同口径重复项、低价值细分项做取舍。一批粘贴不代表全量入库。入选项按指标码去重，保留插插件路径、名称和层级，核对参数顺序、枚举、来源、单位和算法。
2. 逐条用 CLI 真实调用，一次只测一个指标，同一调用可放多家公司和报告期。按插件原文核对证券代码、期间、报表类型、币种及单位，记录使用的参数、原始值与错误。
3. 首轮用有对应报告且业务有代表性的多家公司。常见科目用公司公告对照单位、正负号、期间及金额。同批其他科目即使已通过，这一条也要有自己的实测值。
4. 遇到全零、空值或异常，先在同一公司与期间用已知可用字段核对取数环境与参数，再选公告明确披露该科目的公司和期间复测。若只有累计披露，先核对能否用前后两份同口径公告验证差额。
5. 单条验收以调用成功、参数明确、返回量级合理且有独立样本印证为准。仍只有零值但有保留价值时标 `verified_with_caveat`。科目备注只留使用限制，实测样本放 `evidence`。
6. 按清单核对入库数量、指标码和路径，用 `lookup` 检查备注适用范围，交付时说明新增、跳过及仍受限的字段。
