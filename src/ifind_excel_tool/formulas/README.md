# 公式库字段说明

## verified-formulas.jsonl（已验证）

每行一条，字段：

| 字段 | 含义 |
|---|---|
| path | 插件函数搜索树路径，斜杠分隔，只到分组层（如资产负债表/流动资产），不含具体科目名。累计与单季度是并列的两个 path（利润表/利润表单季度、现金流量表/现金流量表单季度，各可带/补充资料子层），不可混用 |
| name / aliases | 中文名与别名，用于检索。name 前导空格（每级4个）是报表内层级缩进，勿 strip；层级同时以 parent_name 标直接上级纯名称（path 相同的父子不另标 path，多层只标直接上级不穿透） |
| indicator | iFinD 指标码 |
| formula_template | 带 {code}/{date}/{type} 占位符的完整公式；喂给 engine 前需自行替换成完整 thsiFinD 公式 |
| definition / algorithm | 只记影响取数、计算或解释的定义和算法。可用简明措辞归纳插件说明。名称已能说明或原文只有套话时留空 |
| parameters | 数组，每项 position/name/meaning/options/default |
| source / unit | 来源与单位，原文为空则留空 |
| example / example_value | 示例公式与实测值 |
| verification | verified 或 verified_with_caveat |
| verified_at / evidence | 验证日期与证据出处 |
| notes | 优先记录从名称看不出的口径、算法差异和使用限制。具体复算过程和来源放 evidence |
| reading_mode | matrix（数值）或 text（文本，走 text_ok=True） |

verified_with_caveat 表示公式正确但有限制条件，返回数据时必须带出 notes 提示。

## 港股、美股财报数据口径

港股、美股财报数据的 iFinD 字段和公司公告字段不完全相同，存在不稳定的勾稽关系，必要时可直接对照公司公告查看原值。

## general-notes.jsonl（通用注释库）

只有同一条规则确实适用于多个科目，才写成通用注释。用最窄的有效路径约束范围，并用 CLI 确认相邻科目不会误命中。单项算法、例外和反例放到对应科目。

| 字段 | 含义 |
|---|---|
| id | 序号，简单递增 |
| scope | 生效范围，按公式 path 前缀匹配；公式 path 以 scope 开头即生效 |
| note | 规则正文 |

lookup 命中公式时，按该公式 path 找出所有前缀匹配的通用注释，作为每条 hit 的 general_notes 一起返回（含 id 与 note）；单条 notes 只放本条专属备注。

前缀匹配是有意设计：scope 写累计报表路径（如现金流量表），其注释会同时命中单季度报表（现金流量表单季度）；scope 写单季度专属路径的注释只命中单季度，不反向命中累计。需要只覆盖某一分支时，把 scope 写到该分支的完整路径层级。

## catalog.jsonl（全量索引，禁止查询）

由 build_catalog.py 从 C:/Program Files/iFinD/etc/datacube/excel_description.dat 生成，30281 条。

内容错误、口径混淆，AI 多次据此取数出错。除用户明确要求外，任何情况下都不得查询此文件，不得用它找候选写法、核对字段、推断参数或补充任何信息。查不到指标时向用户要插件界面原文。

## 数据来源等级（2026-11-18 踩坑后定）

用户从 iFinD 插件界面手动复制的公式原文属于正式库来源，实测用于确认实际调用、参数和数据口径。真实 Excel 取数且人工确认的结果也可作为证据。

`candidate-formulas.jsonl` 用于登记待核对公式。旧索引只提供检索线索。批量收到的插件公式是筛选素材，正式库只录入有明确用途的指标。入选指标若多次返回 0 或口径仍待确认，记录已知写法、实测情况和限制。

不可靠来源：catalog.jsonl（来自 excel_description.dat，信息可能旧/错/笼统）、2018手册、历史仓库、AI 自己填的 path/name/source/unit。严禁查询、核对或覆盖已验证库。

具体教训：
- 不得拿 catalog 的 source/unit 覆盖已有记录。曾把用户实测的港元数据「港元」改成 catalog 的「元」，把对值改错。原文为空就留空，不从其他市场推断。
- 枚举只认用户贴的参数说明或实测确认的，不从相似指标搬。曾把 ths_close_price_stock 的105/106/101/102 误塞给 close_no_forward（插件只有100/107/108）。
- path/name 以用户从插件界面贴的为准，不自己按理解填，不从历史仓库路径映射推测。
- 无 example_value 的记录不得标 verified，只能 verified_with_caveat。
- 修正须经 update_verified.py 并记录到 correction-log.jsonl；修正只改用户确认过的字段。

总原则：宁可库里少几条，不能有一条错的。

## 批量公式录入与验证流程

1. 通读原文后先筛选。优先录入研究中常用、覆盖已知缺口，或提供独立数据口径的字段。对同口径的重复项、缺乏明确用途的细分项和低价值字段做取舍。一批粘贴不代表全量入库，验收以筛选后的清单为准。入选项按指标码去重，保留插件路径、名称和层级，核对参数顺序、枚举、来源、单位和算法。缺少关键说明时查用户原文或当前插件界面。
2. 逐条用公式 CLI 真实调用，一次只测一个指标，同一调用可以放多家公司和报告期。按插件原文核对证券代码、期间、报表类型、币种及单位，记录使用的参数、原始值和错误。默认用同一口径做横比，常用的非默认写法按需要补测。枚举按插件原文录入，备注区分已实测写法和仅由插件说明支持的写法。
3. 首轮用有对应报告且业务有代表性的多家公司。常见科目用公司公告对照单位、正负号、期间及金额。同批其他科目即使已通过，这一条也要有自己的实测值。字段与公告存在差异时，记录样本中的可复核勾稽关系；无法确定归类时，记录差异和适用范围。
4. 遇到全零、空值或异常，先在同一公司与期间用已知可用的邻近字段核对取数环境、参数及报告覆盖，再选公告明确披露该科目的公司和期间复测。按科目特征挑行业和样本，单季优先使用直接披露该季数据的公司，必要时换财年或季度。若只有累计披露，先核对能否用前后两份同口径公告验证差额，或用完整季度序列与年度累计交叉核对；这两类证据都需写明比较口径。仅有中报或年报金额时，要标明其累计期间。
5. 单条验收以调用成功、参数明确、返回量级合理且有独立样本印证为准。按第 4 步补测后仍只有零值或有口径反例，且字段仍有保留价值时，标为 `verified_with_caveat`。科目备注只留使用限制，实测样本和复算过程放 `evidence`。缺正式路径、关键参数或无法实测时，只登记有明确后续用途的待补项。
6. 按筛选清单核对入库数量、指标码和路径。用 CLI `lookup` 检查专用备注和通用注释的适用范围。交付时说明新增、跳过及仍受限的字段。
