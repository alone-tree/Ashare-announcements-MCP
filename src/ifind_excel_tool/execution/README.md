# 第五块 执行层

和 Excel 直接打交道的一层。用户与调用的 AI 都不需要处理它，只需要它可靠。

`engine.py` 全文不出现任何业务概念（不知道有毛利率、不知道什么是科目），只认
「公式字符串」和「一块单元格」。

## 对外能力

| 函数 | 用途 |
|---|---|
| `fetch_matrix(matrix)` | 日期×字段矩阵批写批读，按行分块 |
| `fetch_formulas(formulas)` | 一列公式批写批读，文本指标走这里 |
| `fetch_table(formula)` | 表函数：写一条公式，等函数把整表写到下方 |
| `open_excel` / `status` / `close_excel` | 专用工作簿生命周期 |
| `get_market_value` | 按日历日取总市值，已实测的模板 |

## 已处理的鲁棒性问题

| 问题 | 处理 |
|---|---|
| Excel 启动慢、反复开关 | 专用工作簿常驻，复用实例 |
| 崩溃后残留恢复提示 | 启动前自动清除本工作簿的恢复残留 |
| 3 万式单批间歇性整批全 0 | 2500 行一批，故障隔离 |
| COM 忙、写入被拒 | 按 1/3/5 秒重试；写入被拒时公式未提交，重写安全 |
| 单元格残留编辑状态 | 向窗口发 Esc 结束编辑 |
| iFinD 弹窗遮挡 | 探测 #32770 窗口并提示关闭 |
| 实例真正僵死 | 结束该进程（只有这种情况才杀） |
| 返回 0 但其实是插件缓存 | 给出 `ZERO_VALUE_HINT`，提示 close 重开 |

实测（2026-11-25）：同一探测公式在重启前返回 0，close 重开后返回正确日期。
所以「取到 0」不能一律当成上游没有数据。

## 加东西的口径

只有两种情况要动这一层：

- 出现了新的 Excel 侧故障，需要新的重试或恢复策略。
- 出现了一种新的取数形态，现有三个函数表达不了。

要注意的判断顺序：COM 报错先看是不是编辑状态或弹窗（可恢复），再看是不是僵死（只能杀）。
不要把可恢复的状态当成僵死处理。

## 边界

本层不判断参数含义、不拼接业务公式、不做单位换算。公式由第一块生成，业务口径由第二块决定。
